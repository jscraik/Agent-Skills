# Cognitive Load Notes

Use this note when a critique needs a sharper read on whether the interface is asking users to think too hard.

## Core rule

Users can only hold a small number of items in working memory at once. Treat more than 4 simultaneous meaningful options at a decision point as a likely overload signal unless the interface clearly groups and guides them.

## Quick checklist

- Single focus: is one action or decision clearly dominant right now?
- Chunking: are options grouped into digestible sets rather than dumped together?
- Recognition over recall: is the information needed for this decision visible now?
- Progressive disclosure: does complexity appear only when needed?
- Context locality: is the supporting evidence near the action instead of hidden elsewhere?

## Common failure patterns

- Wall of options: too many equivalent controls shown at once
- Memory bridge: the user must remember earlier context to finish the current step
- Hidden navigation: the user must construct a mental map instead of following a clear path
- Visual noise floor: everything has equal weight, so nothing stands out
- Context switching: the user must bounce between chat, modal, side panel, or tabs to make one decision

## What to do when it fails

- Reduce simultaneous choices.
- Group related options and show one recommended path.
- Keep evidence and action closer together.
- Split complex work into explicit stages.
- Remove decorative noise before adding polish.
