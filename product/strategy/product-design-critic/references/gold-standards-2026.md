# Gold Standards and Official References (March 2026)

Last reviewed: 2026-03-16
Review policy: prefer official standards and first-party design-system documentation before secondary commentary.

## 1. Normative accessibility standards

- WCAG 2.2 (W3C Recommendation): https://www.w3.org/TR/WCAG22/
- WCAG overview and version guidance: https://www.w3.org/WAI/standards-guidelines/wcag/
- WAI-ARIA Authoring Practices Guide (APG): https://www.w3.org/WAI/ARIA/apg/

How to use in critique:
- map recommendations to perceivable/operable/understandable/robust outcomes
- validate keyboard and assistive-tech behavior for widgets and critical flows

## 2. Trust and governance standards for AI-assisted products

- NIST AI RMF hub: https://airc.nist.gov/
- NIST GenAI Profile publication page: https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence

How to use in critique:
- require transparency, accountability, and risk controls where decisions have impact
- verify provenance, human review points, and reversibility for high-stakes operations

## 3. Official platform and system references

- Apple Human Interface Guidelines: https://developer.apple.com/design/human-interface-guidelines/
- Fluent 2 design system: https://fluent2.microsoft.design/get-started/design
- Fluent 2 design tokens: https://fluent2.microsoft.design/design-tokens
- GOV.UK Design System: https://design-system.service.gov.uk/
- USWDS: https://designsystem.digital.gov/
- USWDS accessibility docs: https://designsystem.digital.gov/documentation/accessibility/

How to use in critique:
- adapt patterns to product context and user risk profile
- avoid cloning vendor UI language if domain constraints differ

## 5. Citation protocol for this skill

For high-stakes recommendations, cite:
- at least one normative standard source
- at least one platform/system source

If no official source is available for a claim, say so explicitly and label it as inferred judgment.
