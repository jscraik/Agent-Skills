Suggestions

  • Add a 'what' clause before the 'Use when' that describes concrete capabilities, e.g., 'Generates hook pack scaffolding, validates hooks.json schema, migrates hook configurations between versions, and troubleshoots hook execution errors.'
  • Expand the action verbs into more specific outcomes — instead of 'creating' say 'scaffolding new hook packs with proper directory structure'; instead of 'validating' say 'checking hooks.json against the expected schema and verifying script permissions'.
  • Add concrete, executable examples: include a complete hooks.json file, a sample hook script, and the exact commands to validate and install them.
  • Drastically reduce the Workflow section by removing internal runtime implementation details (plugin substitutions, compact stdout behavior, managed-only mode nuances) and moving them to a referenced file.
  • Replace the vague Examples section with 1-2 full input/output demonstrations showing a hook pack creation from start to finish with actual file contents.
  • Consolidate the Gotchas, Anti-Patterns, Constraints, and Execution Boundaries sections—they overlap significantly and could be a single concise 'Rules' section.
