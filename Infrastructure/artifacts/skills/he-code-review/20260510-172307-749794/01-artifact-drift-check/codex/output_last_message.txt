I checked the changed HE references/scripts against the live stage contracts and routing map. Short version: the new `he-phase-heartbeat` surface is mostly wired through the right places, but there are two alignment problems that should be fixed before trusting the routing contract.

**Findings**

1. [Infrastructure/scripts/lifecycle-and-sync/route_skillset.py](/Users/jamiecraik/dev/agent-skills/Infrastructure/scripts/lifecycle-and-sync/route_skillset.py:294) violates the documented direct-stage precedence.

`deterministic-stage-routing.md` says direct valid `he-*` stage mentions win unless the user asks whether the stage is correct: [Plugins/harness-engineering/references/deterministic-stage-routing.md](/Users/jamiecraik/dev/agent-skills/Plugins/harness-engineering/references/deterministic-stage-routing.md:7).

But the router checks `is_he_phase_heartbeat_request(...)` at lines 294-300 before direct-stage invocation at lines 301-312. That means a prompt that explicitly names `he-heartbeat` but also contains phase/gate language can be rerouted to `he-phase-heartbeat`, despite the direct stage mention rule. Example shape: “Use `he-heartbeat` to monitor this plan phase until review gates pass.” The phase predicate can win before the explicit `he-heartbeat` mention is honored.

Recommended fix: move direct-stage invocation ahead of the hardcoded phase-heartbeat predicate, or make the phase predicate skip when any explicit non-`he-phase-heartbeat` stage is mentioned.

2. [Plugins/harness-engineering/references/routing-map.json](/Users/jamiecraik/dev/agent-skills/Plugins/harness-engineering/references/routing-map.json:316) still has the old forward lifecycle route.

The deterministic routing doc now says new lifecycle work flows through `he-brainstorm -> he-strategy` or `he-refactor` when needed, then `he-linear-plan` when tracker routing is needed, then `he-spec -> he-plan -> he-work`, with approved recurring execution through `he-phase-heartbeat`: [Plugins/harness-engineering/references/deterministic-stage-routing.md](/Users/jamiecraik/dev/agent-skills/Plugins/harness-engineering/references/deterministic-stage-routing.md:23).

But `routing-map.json` still says:

`he-brainstorm -> he-spec -> he-plan -> he-work`

at [routing-map.json](/Users/jamiecraik/dev/agent-skills/Plugins/harness-engineering/references/routing-map.json:318). Since `route_skillset.py` is supposed to apply `routing-map.json` before keyword matching, this keeps the executable routing map behind the reference doc for the new strategy/refactor/Linear/phase-heartbeat lifecycle.

Recommended fix: update the `forward-lifecycle` route string in `routing-map.json` to match the deterministic routing doc, or simplify it to `he-router` if multi-stage lifecycle routing must remain a router-owned decision.
