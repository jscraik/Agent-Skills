  In the hook entry that invokes `/Users/jamiecraik/dev/agent-skills/Plugins/harness-engineering/scripts/guard.py`, the plugin becomes non-portable. This also violates the spirit of plugin shipping: the hook should bind to the script relative to the plugin/install location, not to one developer’s source tree.


  or:

  ```json
  "command": "./Plugins/harness-engineering/scripts/guard.py"
  ```

  or a small wrapper/launcher that derives the plugin root before executing `scripts/guard.py`.

  If this `hooks/hooks.json` is itself inside the plugin package, the most robust shape is usually to make the command relative to that hook file or to the plugin root, for example `scripts/guard.py`, assuming the hook runner supports plugin-relative paths.
