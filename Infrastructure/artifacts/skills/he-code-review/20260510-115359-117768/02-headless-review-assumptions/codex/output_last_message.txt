Yes. For unattended reviews, I’ll avoid asking non-blocking questions and instead include an **Assumptions** section with confidence levels.

I’ll treat questions as blockers only when the review genuinely cannot proceed without an answer. Otherwise I’ll write them like:

```md
Assumptions
- Assumed the new behavior is intended to preserve the existing API contract. Confidence: high.
- Assumed the changed validation path is only used for admin-created records. Confidence: medium.
- Assumed follow-up migration/backfill is handled separately. Confidence: low.
```

And review findings will stay decisive: if an assumption materially affects risk, I’ll call that out in the finding instead of pausing the review.
