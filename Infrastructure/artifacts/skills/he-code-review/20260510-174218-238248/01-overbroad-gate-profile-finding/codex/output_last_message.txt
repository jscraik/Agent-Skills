**Findings**

- P1 [Infrastructure/scripts/validate_all.sh](/Users/jamiecraik/dev/agent-skills/Infrastructure/scripts/validate_all.sh:351): Out-of-scope checks in changed-files mode are recorded as `blocked` under their original `required` mode instead of as skipped/not-applicable. Because almost every gate is scheduled as `required` later in the file, a docs-only change that should only need docs/progressive-disclosure style proof still emits blocked required rows for unrelated lifecycle, catalog, runtime-separation, projection, and router gates. That is an over-broad gate profile and a real readiness risk: downstream closeout/selection severity can read “docs-only scope” as “required gates blocked,” so agents either cannot close harmless documentation changes or learn to ignore noisy blockers. Minimal fix: when `should_run_check "$slug"` is false, write a distinct `skipped`/`not_applicable` outcome that is excluded from required readiness, or schedule the check only after scope filtering so out-of-scope gates never enter the required gate matrix.

- P1 [Infrastructure/scripts/validate_all.sh](/Users/jamiecraik/dev/agent-skills/Infrastructure/scripts/validate_all.sh:621): `selection-gate-severity` is itself required and consumes the check-results artifact, but the artifact now includes required blocked rows for checks intentionally outside changed-files scope. That makes the readiness summary conflate “not needed for this docs-only diff” with “required proof missing.” This undercuts the HE gate-selection contract’s smallest-sufficient-proof model and creates false negative readiness for trivial/docs-only work. Minimal fix: teach `verify_selection_gate_severity.py` to ignore scoped-out/skipped checks, or change `validate_all.sh` so scoped-out checks are not recorded as required blockers before this severity artifact is generated.
