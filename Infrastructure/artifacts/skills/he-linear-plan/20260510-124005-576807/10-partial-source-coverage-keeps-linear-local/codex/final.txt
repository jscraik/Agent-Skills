**Project Name**
Close Uninspected Prompt-Method Coverage

**Status**
Active

**Project Description**
Upstream source-prompt coverage is currently partial. This project closes all uninspected prompt-method concerns by inventorying every prompt-method source path, classifying inspected vs uninspected coverage, validating prompt behavior against canonical source ownership and runtime projection rules, and creating follow-up fixes for any gaps found.

The project is complete when every prompt-method concern has one of: inspected and accepted, inspected with remediation merged, intentionally out of scope with documented rationale, or superseded by a canonical source decision.

**Project Goals**
- Produce a complete inventory of upstream source-prompt methods and prompt-bearing entry points.
- Identify every uninspected or partially inspected prompt-method concern.
- Inspect each concern against canonical source ownership, runtime projection boundaries, policy sync behavior, and agent-facing documentation expectations.
- Create and close remediation issues for stale, contradictory, duplicated, or projection-owned prompt guidance.
- Add validation evidence so future changes do not silently reintroduce partial prompt coverage.
- Publish a final closeout summary linking inspection evidence, fixes, and accepted residual risk.

**Suggested Milestones**

1. **Inventory**
   - Find all upstream source-prompt locations.
   - Map prompt-method ownership and runtime projection boundaries.
   - Identify prompt-producing commands, templates, docs, skills, and sync inputs.
   - Output: canonical prompt-method inventory.

2. **Gap Classification**
   - Classify inspected, partially inspected, and uninspected prompt-method concerns.
   - Group concerns by owner, source path, generated projection, and validation surface.
   - Output: gap matrix with explicit disposition for every concern.

3. **Inspection**
   - Review uninspected prompt-method concerns.
   - Check for stale guidance, conflicting instructions, source/projection drift, missing policy sync, and undocumented behavior.
   - Output: inspection notes and linked remediation tickets.

4. **Remediation**
   - Fix canonical sources where needed.
   - Remove or update stale generated guidance through the proper source path.
   - Add tests or prove commands where coverage should be enforceable.
   - Output: merged fixes or documented non-fix dispositions.

5. **Closeout**
   - Run repo validation and changed-file closeout.
   - Confirm all concerns have final disposition.
   - Publish summary with remaining risks, if any.
   - Output: project closeout note and evidence links.

**Starter Issues**

1. **Inventory all upstream source-prompt methods**
   - Find every canonical prompt-bearing source, command, template, skill, operator doc, and runtime projection input.
   - Include exact paths and ownership boundaries.
   - Acceptance: inventory lists every known prompt-method source and marks whether it is canonical, generated, or derived.

2. **Map prompt-method concerns to inspected coverage**
   - Build a matrix of prompt-method concerns and whether each has already been inspected.
   - Acceptance: every concern is marked `inspected`, `partial`, `uninspected`, `out of scope`, or `superseded`.

3. **Identify uninspected source-prompt paths**
   - Search for prompt construction, source prompt templates, sync inputs, skill prompts, and operator prompt docs that were omitted from prior inspection.
   - Acceptance: all uninspected paths are linked to inspection issues or explicitly ruled out.

4. **Inspect canonical source ownership for prompt-method concerns**
   - Verify prompt changes belong in canonical sources rather than runtime projections.
   - Acceptance: every concern has an owner path and no remediation targets generated-only projections unless the projection system itself is the defect.

5. **Inspect runtime projection drift**
   - Compare canonical prompt sources against runtime projections where applicable.
   - Acceptance: drift is either fixed through source regeneration or documented as expected.

6. **Inspect policy sync prompt behavior**
   - Review sync policy prompt paths and generated outputs for stale or contradictory guidance.
   - Acceptance: policy sync behavior is verified with command evidence or follow-up remediation.

7. **Inspect agent-facing docs for prompt-method contradictions**
   - Review agent docs that influence prompt construction or agent behavior.
   - Acceptance: contradictions are removed, consolidated, or linked to deliberate precedence rules.

8. **Inspect skill prompt-method coverage**
   - Review skills that generate, transform, install, audit, or prove prompts.
   - Acceptance: skill prompt behavior is covered by inspection notes and validation evidence.

9. **Inspect command-level prompt generation**
   - Review repo wrappers and command paths that construct prompts, especially `./bin/ask` workflows.
   - Acceptance: command-level prompt construction has explicit source mapping and validation.

10. **Inspect generated artifacts and stale projections**
   - Locate generated prompt artifacts that may be stale or incorrectly treated as source.
   - Acceptance: stale projections are regenerated or tracked as cleanup work.

11. **Create remediation issues for every validated prompt-method gap**
   - Split remediation by ownership area so fixes remain reviewable.
   - Acceptance: no validated concern remains only in notes; each has a Linear issue or documented non-fix disposition.

12. **Add validation coverage for prompt-method closure**
   - Identify prove, doctor, or closeout commands that should guard future prompt-method drift.
   - Acceptance: final validation command list exists and each command has pass/fail evidence.

13. **Run final project closeout**
   - Confirm every issue is closed, linked, or explicitly deferred.
   - Acceptance: closeout summary includes inventory, inspection matrix, remediation links, validation evidence, and residual risk.

**Definition Of Done**
- 100% of prompt-method concerns have a final disposition.
- No uninspected prompt-method concern remains in the matrix.
- All validated defects have either merged remediation or a linked active follow-up with rationale.
- Canonical source vs runtime projection ownership is clear for every touched area.
- Final validation evidence is attached to the project.
- Closeout summary states whether upstream source-prompt coverage is now complete, conditionally complete, or complete with documented exclusions.
