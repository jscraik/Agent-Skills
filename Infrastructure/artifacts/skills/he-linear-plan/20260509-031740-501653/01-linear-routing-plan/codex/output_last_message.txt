### Milestone 1: Agent Cockpit Compression Slice
Scope: JSC-282 and JSC-283 together.

Goal: reconcile command truth for the PR-loop cockpit, then prove the packaged skill can drive the selected cockpit command path in a downstream-like setup.

Gates:
- SA-010 command truth inventory
- SA-011 mismatch classification
- SA-012 command tiering
- SA-013 legacy owner, validation, and sunset rules
- SA-014 command projection validation
- SA-015 first cockpit dispatch or demotion proof
- SA-020 fixture matrix
- SA-021 static validation remains active
- SA-022 clean install/init fixture proof or explicit blocker
- SA-023 update/idempotence fixture proof or explicit blocker
- SA-024 command reference resolution proof
- SA-030 eval artifact for command truth reconciliation
- SA-031 eval artifact for packaged skill behavior assurance
- SA-033 rollback conditions
- SA-034 preservation of `harness next --json`, `HarnessDecision`, and exit-code contracts

Exit rule: do not widen scope until command truth, fixture behavior, and rollback conditions are all proven.

### Milestone 2: Governance Trust Repair Slice
Scope: JSC-288.

Goal: resolve memory ownership, governance surface ownership, and contract bounded-context design so future agents can distinguish executable policy from stale or symbolic guidance.

Gates:
- docs lint for changed durable markdown
- contract validation or focused type/test gates if contract behavior changes
- memory health and provenance checks if memory surfaces change
- governance drift evaluation before closure
- rollback conditions that preserve published contract compatibility and discoverability

Dependency note: this slice is blocked until the cockpit slice has local closure proof.

### Milestone 3: CI Migration Boundary Recovery Slice
Scope: JSC-289.

Goal: characterize current CI migration behavior and define the first safe extraction boundary without changing public command behavior.

Gates:
- focused CI migration tests
- typecheck
- lint
- `bash scripts/verify-work.sh --fast` where feasible
- architecture drift evaluation
- CI migration boundary recovery eval artifact
- rollback conditions that prevent behavior changes before parity proof exists

Exit rule: keep extraction strictly behind characterization proof and avoid deleting legacy paths before parity is established.

**Working Rule**
- Keep the active set small.
- Do not expand into broader legacy cleanup, new plugins, UI work, or unrelated refactors until the matching milestone gates are closed.
