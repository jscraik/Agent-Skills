**Milestone 1: Workflow baseline locked**
- Scope: confirm templates, saved views, and blocked-routing convention.
- Gate:
  - templates exist for Bug, Feature, Research, Automation, and Release
  - saved views exist for Triage, Ready, In Progress, In Review, Blocked, and Delegated
  - `Blocked` is documented as a label plus dependency relation, not a workflow status

**Milestone 2: Linear-first execution flow**
- Scope: make Linear the canonical place for claim, handoff, and close behavior.
- Gate:
  - claim / handoff / close behavior is implemented or explicitly staged
  - transitions are deterministic and documented
  - evidence, PR links, and blocker notes are first-class execution artifacts
  - repo guidance matches the implemented behavior

**Milestone 3: GitHub and release loop**
- Scope: keep GitHub branch and PR automation wired back to Linear, and use Linear releases for shipped output.
- Gate:
  - branch naming preserves `codex/` and includes the Linear key where practical
  - PR links and branch activity reflect back onto Linear issues
  - merge-time closeout behavior is predictable and documented
  - release notes can be generated from the Linear release with minimal cleanup

**Operating rules**
- Keep live state in Linear, not in this plan.
- Use the live ledger for execution truth and blockers.
- Treat this as sequencing guidance, not cycle-by-cycle status.
- If a gate is not met, stop at that milestone and split the gap into a follow-up issue before expanding scope.
