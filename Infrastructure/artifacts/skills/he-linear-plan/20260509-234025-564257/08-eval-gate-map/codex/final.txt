The minimum gate bundle I’d attach to every parent issue is:

```bash
./bin/ask repo doctor --json --robot
./bin/ask skills explain <handle> --json --robot
./bin/ask skills prove <handle> --json --robot
./bin/ask repo closeout --changed --json --robot
```

For parent issues that touch multiple skills, the gate expands to one `skills explain` and one `skills prove` per affected handle.

The strongest mapping rule is:

| Gate Type | What It Protects |
|---|---|
| Build | Package/tooling still compiles or assembles where applicable. |
| Test | Changed behavior is proven through skill proof, package tests, or focused scenarios. |
| Drift | Canonical sources, runtime projections, generated docs, and ownership boundaries remain aligned. |
| Routing | Agents discover and invoke the intended skill/workflow, without broadening or shadowing adjacent routes. |
| Rollback | The issue can be reverted cleanly without damaging unrelated work or leaving generated/runtime state inconsistent. |
