Here’s a small Linear-ready execution plan distilled from the approved harness artifacts.

**Project:** `Skill Authoring Family Iteration Upgrade`

**Milestone 1: Creator handoff contract**
- Scope: make the creator-to-builder transition explicit and durable.
- Deliverables: target-skill `handoff-package` contract, reusable template, creator metadata/signposting.
- Gate: creator docs and template agree on the handoff artifact path and required fields.
- Exit check: docs lint and creator quick validation pass.

**Milestone 2: Builder round model and evidence surface**
- Scope: define the explicit comparative round loop for `skill-builder`.
- Deliverables: round vocabulary, baseline-selection rules, frozen comparison inputs, evidence ownership map, report-shape guidance.
- Gate: builder documentation makes it unambiguous which artifact is canonical for narrative review, CI gating, and release snapshotting.
- Exit check: no new viewer or parallel workspace is introduced; changes stay additive.

**Milestone 3: Eval harness enforcement**
- Scope: make the new round model enforceable.
- Deliverables: updated eval cases, backward-compatible report fields, readiness-state handling, baseline provenance, optional human-review surface if needed.
- Gate: `summary.json` and per-case `result.json` carry the new metadata without breaking current consumers.
- Exit check: harness regression tests pass, including the targeted iteration-upgrade case.

**Milestone 4: Downstream gating and sync**
- Scope: align installer and plugin-builder with the new evidence model.
- Deliverables: downstream-only language, `ContractValidityEvidence` references, catalog/sync refresh if user-facing text changed.
- Gate: downstream surfaces cannot self-attest lifecycle validity.
- Exit check: docs lint passes and skill sync completes cleanly.

**Milestone 5: Integrated validation and closeout**
- Scope: prove the full chain is coherent.
- Deliverables: final validation sweep, plan closeout evidence, residual-risk notes if anything is still environmental.
- Gate: do not mark complete until the full validation stack passes or a concrete blocker is documented.
- Exit check: broad repo validation passes, or the smallest safe follow-up is recorded.

**Suggested Linear issue breakdown**
1. `P0 - Creator handoff contract`
2. `P1 - Builder round contract`
3. `P2 - Eval harness updates`
4. `P3 - Downstream gating + sync`
5. `P4 - Integrated validation + closeout`

**Primary gates to use in Linear**
- Contract clarity gate: source artifacts and target file paths are explicit.
- Backward-compatibility gate: existing report consumers still work.
- Harness gate: targeted evals and regression tests pass.
- Sync gate: public-facing docs and generated surfaces are aligned.
- Closeout gate: repo-wide validation passes or the blocker is captured precisely.
