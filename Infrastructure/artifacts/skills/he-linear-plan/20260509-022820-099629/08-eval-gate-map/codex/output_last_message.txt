Why that mapping:

- [JSC-216](https://linear.app/jscraik/issue/JSC-216/agent-design-engine-pre-ga-hardening)
  - `test` is primary because the scope explicitly includes quarantine and concurrent-writer race coverage, plus recovery fixture completeness.
  - `rollback` is primary because the scope includes crash-safe migration transition behavior and rollback metadata authenticity/compatibility checks.
  - `drift` matters because the contract has to keep migration and recovery behavior from drifting across wrapper/engine boundaries.
  - `build` and `routing` are not the main focus of this parent.

- [JSC-223](https://linear.app/jscraik/issue/JSC-223/repo-wide-audit-dead-code-generated-artifacts-and-design-system-bloat)
  - `build` is primary because [JSC-225](https://linear.app/jscraik/issue/JSC-225/decide-tracked-build-output-and-screenshot-artifact-contract) is about build outputs and screenshot artifacts.
  - `test` is primary because the parent explicitly requires validation, and [JSC-226](https://linear.app/jscraik/issue/JSC-226/define-generated-source-regeneration-contract) and [JSC-228](https://linear.app/jscraik/issue/JSC-228/add-guard-for-newly-tracked-ignored-runtime-artifacts) both need freshness and guard checks.
  - `drift` is primary because the whole track is about stopping generated/runtime artifacts and ignored files from drifting out of policy.
  - `routing` matters because [JSC-229](https://linear.app/jscraik/issue/JSC-229/review-orphaned-scripts-and-prototype-package-lifecycle) is explicitly about deciding whether scripts are wired, dormant, or archived.
  - `rollback` matters where cleanup needs a documented regeneration path or a revert-safe policy for intentional artifacts.
