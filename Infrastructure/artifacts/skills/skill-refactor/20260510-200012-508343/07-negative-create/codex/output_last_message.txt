# AGENTS.md Instruction Compliance

Use this skill whenever work may touch files governed by one or more `AGENTS.md` files, especially in repositories or containers where instruction files can appear at `/`, `~`, repo roots, or nested directories.

## Core Rule

`AGENTS.md` files are human guidance for agents. They may define coding standards, project layout, build and test steps, wording requirements, PR conventions, safety rules, or other task-specific expectations.

An `AGENTS.md` governs the directory that contains it and every child directory beneath that point.

## Discovery Workflow

1. Identify the files or directories the task may touch.
2. Search upward from each target path for every applicable `AGENTS.md`.
3. Also account for any `AGENTS.md` content already provided by the user or system context.
4. Read only the instruction files needed for the target scope.
5. Before editing, summarize any task-relevant constraints if they affect the implementation path.

Prefer fast search tools when available:

```bash
rg --files -g 'AGENTS.md'
```

For a specific target file, check its ancestor directories from the filesystem root down to the file’s parent directory.

## Precedence

Apply instructions in this order:

1. System, developer, and direct user instructions have highest priority.
2. Deeper `AGENTS.md` files override higher-level `AGENTS.md` files when they conflict.
3. Instructions from an `AGENTS.md` apply only within that file’s directory subtree unless explicitly stated otherwise.
4. If two applicable instructions do not conflict, follow both.

## Editing Rules

Before changing a file:

1. Confirm which `AGENTS.md` files govern that path.
2. Apply all relevant style, validation, workflow, and safety instructions.
3. Edit canonical sources rather than generated outputs or runtime projections when the instructions distinguish ownership.
4. Preserve user work and unrelated changes.
5. Do not revert files simply because they differ from the expected baseline.

When moving or creating files, determine the destination scope and apply the instructions for the destination path.

## Validation

After changes:

1. Run the validation commands required by the applicable instructions.
2. If a repo wrapper is required, use it instead of direct package commands.
3. If validation cannot run, report the exact command attempted and the blocker.
4. Include pass/fail evidence in the final response.

## Common Pitfalls

- Assuming only repo-root `AGENTS.md` matters.
- Ignoring nested instruction files.
- Applying instructions outside their scoped directory.
- Editing generated projections when the repo requires canonical source edits.
- Letting lower-priority instruction files override direct user, developer, or system instructions.
- Skipping required repo bootstrap or wrapper commands.
