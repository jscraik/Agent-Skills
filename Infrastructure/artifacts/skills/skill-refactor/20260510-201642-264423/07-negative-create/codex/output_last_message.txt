## Command Policy

The repository root has no package manager install step.

At the repo root:

- Use repo wrappers.
- Do not run package-manager commands unless you have verified you are inside a package root.
- Prefer `./bin/ask` for repository operations.

Common commands:

```bash
./bin/ask repo doctor --json --robot
./bin/ask skills improve "<goal>" --json --robot
./bin/ask skills explain <handle> --json --robot
./bin/ask skills prove <handle> --json --robot
./bin/ask repo closeout --changed --json --robot
```

Use `--json --robot` when collecting machine-readable evidence.

## Workflow

1. Orient with repo status and applicable instructions.

   ```bash
   ./bin/ask repo doctor --json --robot
   ```

2. Identify the canonical file or skill source to edit.

   Check path ownership before touching runtime projections.

3. Make the smallest scoped change that satisfies the request.

   Preserve user work and avoid unrelated refactors.

4. Validate the changed skill or workflow.

   For a skill handle:

   ```bash
   ./bin/ask skills explain <handle> --json --robot
   ./bin/ask skills prove <handle> --json --robot
   ```

5. Run closeout for changed files:

   ```bash
   ./bin/ask repo closeout --changed --json --robot
   ```

6. Report exact pass/fail evidence.

   Include command names and concise outcomes.

## AGENTS.md Handling

AGENTS.md files can exist anywhere and apply to the directory containing them and all descendants.

When changing a file:

1. Find applicable `AGENTS.md` files from the target path upward.
2. Follow all applicable instructions.
3. If instructions conflict, the deeper `AGENTS.md` wins.
4. System, developer, and user instructions outrank AGENTS.md.

Do not assume AGENTS.md files only exist in git-tracked directories.

- the failure mode
