# AGENTS.md Instruction Handling

Use this skill when a task involves `AGENTS.md` files, repo-local agent instructions, scoped coding guidance, or conflicts between human-authored agent instructions.

## Core Rule

`AGENTS.md` files are human guidance for agents. They may appear anywhere in a filesystem, including `/`, `~`, repository roots, package directories, or deeply nested folders. An `AGENTS.md` governs the directory that contains it and every child path beneath that directory.

Before editing a file, identify every `AGENTS.md` whose scope covers that file and follow all applicable instructions.

## Precedence

Instruction precedence is:

1. System, developer, and direct user instructions.
2. Deeper `AGENTS.md` files.
3. Higher-level `AGENTS.md` files.

When two `AGENTS.md` files disagree, the deeper file wins for files under its directory. When a prompt instruction conflicts with any `AGENTS.md`, the prompt instruction wins.

## Discovery Workflow

1. Start from the target file or directory.
2. Walk upward toward filesystem root.
3. Collect every `AGENTS.md` along that path.
4. Read the highest-level applicable file first, then progressively deeper files.
5. Apply deeper instructions as refinements or overrides.
6. Before changing files, confirm the target path is covered by the instructions you are applying.

Use fast search tools such as `rg --files -g AGENTS.md` when available. If repo-specific tooling exists, prefer it when the root instructions require it.

## Applying Instructions

For every covered file change:

- Obey coding, formatting, validation, commit, PR, and workflow rules from applicable `AGENTS.md` files.
- Treat naming conventions and style rules as scoped to the directory governed by the file unless explicitly stated otherwise.
- Do not apply instructions from sibling or unrelated directories.
- If instructions reference canonical source paths, edit those sources rather than generated runtime projections.
- If instructions require reading supporting docs before edits, read only the docs needed for the task.

## Conflict Handling

If instructions conflict:

- Prefer direct user or higher-priority system/developer instructions.
- Prefer the deeper `AGENTS.md` for path-scoped conflicts.
- If the conflict blocks implementation and cannot be resolved by precedence, ask the user.
- If stale or contradictory guidance is discovered during an instruction cleanup task, preserve evidence and propose or implement a targeted fix.

## Repo Workflow Pattern

When a repository root `AGENTS.md` defines required wrappers or validation commands:

1. Bootstrap required tooling before depending on wrapper commands.
2. Use repo-provided wrappers for repo operations.
3. Avoid package-manager commands at the repo root unless the instructions explicitly allow them.
4. Run the validation or closeout command named by the repo guidance before claiming completion.

For the `agent-skills` repository specifically:

- Run `bash scripts/bootstrap-ask.sh --json` on a fresh checkout before requiring `./bin/ask`.
- Use `./bin/ask` for repo operations.
- Read `UBIQUITOUS_LANGUAGE.md` before changing skills, sync policy, runtime projections, or agent-facing docs.
- Edit canonical sources, not runtime projections.
- Use `./bin/ask repo closeout --changed --json --robot` when validating changed work.

## Completion Checklist

Before final response:

- Applicable `AGENTS.md` files were identified.
- Target files were checked against scoped instructions.
- Deeper instructions were applied where relevant.
- Required repo wrappers or validation commands were run, or the blocker is stated.
- Final response includes exact paths changed and pass/fail validation evidence.
