The closure blockers are:

1. **Bounded context is not identified**
   The slice needs to name which domain context owns the behavior, vocabulary, rules, and lifecycle. Without that, reviewers cannot tell whether the implementation belongs in the current module, crosses context boundaries incorrectly, or leaks another domain’s concepts into this one.

2. **Aggregate boundary is not proven**
   The owning aggregate needs to be explicit. The closure evidence should show which entity or aggregate root enforces the rule, which state transitions are allowed, and which objects are merely referenced instead of mutated.

3. **Aggregate invariant is not stated**
   The invariant should be written as a domain rule, not as an implementation detail. For example:

   ```text
   A SkillProjection must never be published unless its canonical SkillSource has passed validation for the same policy version.
   ```

   The exact invariant depends on the slice, but it needs to be concrete enough that tests can prove it.

4. **Invariant proof is missing**
   Closure needs evidence that the invariant is enforced across create, update, delete, sync, projection, import, and retry paths as applicable. A single happy-path test is not enough for a domain-sensitive rule.
