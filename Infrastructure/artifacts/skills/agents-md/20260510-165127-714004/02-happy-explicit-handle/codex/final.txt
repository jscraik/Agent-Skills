**What Stays In Root AGENTS.md**

Keep the minimum instruction surface that an agent needs before touching `apps/web/**`:

```md
# apps/web Agent Guide

This directory contains the web application workspace. Follow the root
repository guidance first, then these web-specific instructions.

## Context Pointers

- For the web app architecture and product/module overview, read:
  `apps/web/docs/README.md` or the web architecture doc.
- For frontend and TypeScript conventions, read:
  `docs/frontend.md`.
- For package scripts and validation commands, read:
  `apps/web/package.json` and the validation docs.
- For shared repo command policy, validation order, and closeout, read the root
  `AGENTS.md` links under `Docs/agents/`.

## Commands

Run commands from `apps/web` unless a command says otherwise.

- Install dependencies only if the package root requires it.
- Lint: `pnpm lint`
- Typecheck/test/build: use the scripts defined in `apps/web/package.json`.

## Local Rules

- Edit source files in `apps/web`; do not edit generated build output.
- Keep UI changes consistent with the existing component, styling, and routing
  patterns in this app.
- When changing shared frontend behavior, validate with the narrowest relevant
  script first, then broader checks if the change crosses module boundaries.
```

That is the kind of content that belongs in an `AGENTS.md`: scope, pointers, commands, ownership boundaries, and local agent-facing constraints.



Delete the copied TypeScript style section from `docs/frontend.md`. Replace with the Context Pointer to `docs/frontend.md`.

Delete any broad project-description prose that does not answer one of these questions:

- What directory does this govern?
- What files are canonical versus generated?
- What commands should an agent run here?
- What docs should an agent read before changing specific kinds of files?
- What local constraints override or specialize root guidance?
