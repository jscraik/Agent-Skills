# ledger-cli Agent Guide

ledger-cli is a small Python command-line application for ledger-oriented workflows. This guide keeps agent work predictable, lightweight, and easy to validate.

## Root Essentials

- Treat this repository as a compact Python CLI project.
- Use `uv` for Python environment and command execution.
- Do not assume a package-manager install step beyond the existing `uv` workflow.
- Prefer small, focused changes that preserve the current CLI behavior unless the task explicitly asks to change it.
- There is currently no Project Brain, memory surface, or persistent agent knowledge base for this repo. Rely on live repository files, tests, and the user’s instructions.

## Repository Orientation

Before making non-trivial changes:

```bash
pwd
rg --files
```

Look for the CLI entry point, package metadata, and tests before choosing an implementation path. Common files may include:

```text
pyproject.toml
README.md
src/
tests/
```

If the project layout differs, follow the live tree rather than assuming a standard structure.

## Common Commands

Run the focused CLI test suite with:

```bash
uv run pytest -q tests/cli
```

Use this as the default validation check for CLI-facing changes.

For broader inspection, useful commands include:

```bash
uv run python --version
uv run pytest -q
uv run python -m ledger_cli --help
```

Only run broader checks when they are relevant, reasonably fast, or requested.

## Development Guidelines

- Keep CLI output stable and intentional. Snapshot-like assertions, help text, exit codes, and stderr/stdout behavior are part of the user-facing contract.
- Preserve backward-compatible command names, flags, argument parsing, and defaults unless the user asks for a breaking change.
- Keep error messages clear, concise, and actionable.
- Prefer standard-library Python where it is sufficient.
- Follow existing code style, naming, and module organization.
- Avoid introducing new dependencies unless they clearly reduce complexity and fit the project’s existing dependency policy.
- Keep changes scoped to the requested behavior. Do not perform unrelated refactors while touching CLI code.

## Testing Guidance

For any change that affects command behavior, parsing, formatting, file I/O, or exit status, add or update tests under the relevant test area, especially:

```text
tests/cli
```

The expected validation command is:

```bash
uv run pytest -q tests/cli
```

If tests cannot be run, report the exact command attempted and the reason it failed.

## Python CLI Notes

When editing CLI behavior, check:

- exit status for success and failure paths
- stdout vs stderr placement
- help text and usage output
- handling of missing, malformed, or conflicting arguments
- behavior when input files or ledger data are absent
- deterministic ordering of displayed output
- compatibility with non-interactive shell usage

Prefer test coverage that exercises the CLI the way a user invokes it, rather than only testing internal helper functions.

## Git And Safety

- Do not revert or overwrite user changes unless explicitly asked.
- Inspect the working tree before making edits when the task involves code changes:

```bash
git status --short
```

- Keep commits, if requested, focused and descriptive.
- Do not include generated caches, virtual environments, or local artifacts in changes.

## Agent Closeout

When finishing a change, report:

- the files changed
- the validation command run
- whether validation passed or failed
- any remaining risk or follow-up that matters

For the standard CLI validation, prefer this evidence format:

```text
Validation: uv run pytest -q tests/cli
Result: pass
```
