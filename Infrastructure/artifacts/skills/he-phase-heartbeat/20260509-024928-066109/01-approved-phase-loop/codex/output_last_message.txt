**Approved Loop**
1. Define the target and assumptions.
2. Plan the work into small, ordered slices.
3. Build one slice at a time.
4. Verify each slice with proof.
5. Review quality and risk.
6. Ship only after the gates pass.

**Checkpoint Rule**
- At the start of each phase, I’ll restate scope, assumptions, and the next smallest deliverable.
- At the end of each phase, I’ll require an explicit proof gate before moving on.

**Proof Gates**
- Define: acceptance criteria or a clear spec.
- Plan: a task breakdown with dependencies and completion criteria.
- Build: a working increment that stays compilable.
- Verify: tests, build, lint, or manual/runtime evidence.
- Review: no blocking quality, security, or performance issues.
- Ship: commit/launch readiness, rollback path, and monitoring if relevant.

**Stop Conditions**
- Requirements are ambiguous.
- A proof gate fails.
- Scope starts expanding beyond the agreed task.
- I find conflicting instructions or missing acceptance criteria.
- The change can’t be kept in a working state between slices.
