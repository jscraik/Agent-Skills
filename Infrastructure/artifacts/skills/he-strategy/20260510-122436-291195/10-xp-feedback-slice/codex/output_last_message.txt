**Smallest Feedback-Producing Slice**

Run one narrow, end-to-end proof that answers this question:

> Can an agent start from one real skill-improvement goal, use the canonical repo workflow, and produce useful, machine-readable feedback before making broad changes?

The slice should be:

1. Pick **one existing skill** with a concrete improvement goal.
   Example: “make this skill clearer about when to stop, validate, or escalate.”

2. Run the canonical command once:

   ```bash
   ./bin/ask skills improve "<one concrete skill-improvement goal>" --json --robot
   ```

3. Capture only the feedback artifacts that matter:
   - Did the command identify the right canonical source?
   - Did it produce a bounded proposed change?
   - Did it name validation/proof steps?
   - Did the JSON output give an agent enough structure to decide the next action?
   - Did it avoid touching runtime projections or unrelated files?

4. Make the smallest possible edit only if the feedback points to one obvious source-file fix.

5. Validate with:

   ```bash
   ./bin/ask skills prove <handle> --json --robot
   ./bin/ask repo closeout --changed --json --robot
   ```

The slice is successful if it produces a concrete loop:

```text
goal -> canonical source identified -> proposed edit -> proof command -> changed-file closeout
```

**Stop Or Pivot Condition**

Stop after one skill and one improvement loop.

Pivot if any of these happen:

- `skills improve` cannot identify the canonical source path confidently.
- The command output is not structured enough for an agent to choose the next action without human interpretation.
- The proposed change requires touching multiple ownership areas, runtime projections, or policy docs.
- `skills prove` does not give clear pass/fail evidence.
- `repo closeout --changed` surfaces unrelated or surprising changes.

If the slice passes, continue by generalizing the loop. If it fails, do not broaden the strategy yet; fix the first broken control-plane step that prevented useful feedback.
