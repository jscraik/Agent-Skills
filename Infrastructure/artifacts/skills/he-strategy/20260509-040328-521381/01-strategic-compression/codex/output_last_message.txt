```md
# Strategic Direction

This repository exists to make agent skills easy to author, validate, discover, and sync across Codex surfaces without turning the system into a rigid, hard-to-debug process machine.

## Direction

We optimize for small, composable, durable skills that preserve operator control.

The system should:
- keep canonical sources lightweight and editable
- separate durable decisions from transient workflow output
- make skill behavior easy to understand from the docs alone
- avoid hiding critical setup behind implicit magic
- prefer clear contracts over broad, procedural automation

## What We Learned

### From intent
The underlying intent is not just to automate workflows. It is to preserve good judgment while reducing repeated explanation and context loss.

That means:
- the repo should encode durable knowledge, not just task-specific instructions
- language matters as much as implementation
- agent behavior should stay legible to humans

### From review
The review signal is that durable artifacts should be behavioral and decision-oriented, not procedural.

So:
- document what should be true, not where to edit code
- record real tradeoffs and constraints
- keep the durable artifacts short enough to survive iteration
- avoid duplicating transient implementation detail in long-lived docs

### From triage
The triage signal is that rejected, deferred, or reclassified work should not disappear into chat history.

So:
- important exclusions belong in persistent out-of-scope records
- ready-for-agent outcomes should become explicit contracts
- unresolved questions should be captured as concrete follow-ups
- repeated requests should resolve against prior decisions, not relitigate from scratch

## Operating Principles

- Keep canonical documents short, opinionated, and easy to scan
- Prefer one clear term for one concept
- Record hard decisions once, then reference them
- Separate durable strategy from operational churn
- Treat docs as a control plane, not an archive dump

## Scope

In scope:
- skill authoring conventions
- durable guidance for agents
- decision records and language normalization
- triage and out-of-scope memory

Out of scope:
- implementation walkthroughs
- transient debugging notes
- per-task scratchpad reasoning
- procedural step lists that will stale quickly

## Success Signals

This strategy is working if:
- a new agent can orient quickly from the docs
- repeated decisions are not re-argued
- skills remain small and composable
- review and triage output can be collapsed into stable guidance
- the repo stays easy to extend without adding process bloat

## Open Questions

- Which artifacts should be promoted into durable docs versus left as ephemeral work logs?
- What is the smallest canonical doc set that still preserves meaning across sessions?
- Where should rejected ideas live so they are easy to rediscover without polluting the main path?
```
