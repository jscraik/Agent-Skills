```markdown
# Strategic Direction

## Purpose

This document compresses the current intent, review findings, and triage artifacts into a durable direction for the work ahead. It is meant to preserve the strategic decisions behind the next implementation moves, reduce repeated rediscovery, and make future agent or human work easier to evaluate.

## Current Intent

The work is centered on moving from scattered operational artifacts toward a coherent control plane for agent skills, operator docs, validation flows, and workflow governance.

The durable intent is to make skills easier to author, validate, discover, improve, and sync while preserving clear ownership boundaries between canonical sources and runtime projections.

The desired end state is a repo where agents can reliably answer three questions before acting:

1. What is the canonical source of truth?
2. What validation proves the change is acceptable?
3. What operational contract governs how this work should be performed?

## Strategic Direction

### 1. Treat Canonical Sources As The Product Surface

The core strategic move is to make canonical skill, policy, and operator documentation the primary editable surface. Runtime projections should remain generated, synced, or derived outputs rather than places where durable decisions live.

This keeps the system legible: agents and humans should be able to inspect canonical paths and understand what governs behavior without reverse-engineering generated runtime state.

### 2. Collapse Scattered Guidance Into Navigable Operating Contracts

Intent, review, and triage artifacts should not remain as isolated notes once their lessons are accepted. Durable findings should be folded into the agent-facing documentation map, especially where they affect:

- path ownership
- command policy
- validation expectations
- skill lifecycle rules
- sync and projection behavior
- review and closeout expectations

The goal is not to preserve every note. The goal is to preserve decisions, invariants, and sharp edges that future work must respect.

### 3. Prefer Proveable Workflow Over Narrative Confidence

The repo should keep pushing toward machine-checkable workflows. Strategic direction should favor commands, JSON output, robot mode, and explicit closeout evidence over prose-only assurance.

Where possible, durable docs should point to concrete commands such as:

```bash
./bin/ask repo doctor --json --robot
./bin/ask skills improve "<goal>" --json --robot
./bin/ask skills explain <handle> --json --robot
./bin/ask skills prove <handle> --json --robot
./bin/ask repo closeout --changed --json --robot
```

A change is strategically complete when the relevant validation path is clear, repeatable, and tied to the ownership boundary it touches.

### 4. Keep Agent Instructions Small, Layered, And Scoped

Agent guidance should remain layered by scope. Root guidance should explain the repo-level contract and point to deeper docs. Deeper docs should override root guidance only where their scope requires more specific behavior.

This prevents AGENTS.md files and skill instructions from becoming bloated catch-alls. The durable pattern is:

- root instructions establish repo invariants
- docs provide the instruction map
- domain-specific files govern local behavior
- skills encode reusable workflows
- generated/runtime projections are not edited as source

### 5. Convert Review Findings Into Maintained Policy

Review artifacts are valuable only if they become one of three things:

- a fixed implementation issue
- an explicit non-goal
- a durable rule in the appropriate canonical doc

Unresolved review findings should not linger as ambient caution. They should be triaged into ownership, severity, next action, and validation evidence.

### 6. Convert Triage Into A Prioritized Change System

Triage artifacts should be compressed into decision records that clarify what matters next. A durable triage outcome should identify:

- the problem being solved
- the affected canonical surface
- the user or agent workflow improved
- the validation command that proves success
- the deferred risks or accepted tradeoffs

Triage should avoid creating parallel planning surfaces. Once a triage decision is accepted, it should move into the docs, issues, or implementation queue that owns the work.

## Operating Principles

### Preserve Source Ownership

Before changing skills, sync policy, runtime projections, or agent-facing docs, read `UBIQUITOUS_LANGUAGE.md` and confirm the relevant path ownership boundary.

Do not edit runtime projections when a canonical source owns the behavior.

### Route Through Repo Wrappers

Use root wrappers for repo operations. The root has no package-manager install step.

Prefer:

```bash
./bin/ask <command> --json --robot
```

Use package-specific commands only after confirming the package root.

### Validate By Blast Radius

Validation should match the changed surface:

- documentation-only changes require doc and closeout evidence
- skill changes require explain/prove flows where applicable
- sync or projection changes require evidence that generated/runtime output remains consistent
- workflow or policy changes require repo doctor and changed-file closeout

### Keep Durable Docs Decision-Oriented

Durable docs should preserve:

- decisions
- constraints
- invariants
- validation paths
- ownership rules
- known tradeoffs

They should not preserve every discussion detail unless that detail materially affects future implementation.

## Near-Term Priorities

### Priority 1: Consolidate Accepted Guidance

Fold accepted lessons from intent, review, and triage artifacts into the canonical docs that govern them. Remove stale or contradictory guidance once replacement guidance exists.

Likely destination areas:

- `UBIQUITOUS_LANGUAGE.md`
- `Docs/agents/README.md`
- `Docs/agents/14-path-ownership-boundaries.md`
- `Docs/agents/16-agent-operating-contract.md`
- `Docs/agents/17-skill-management.md`
- `Docs/agents/05-contradictions-and-cleanup.md`

### Priority 2: Make Validation Paths Obvious

Every durable strategy or workflow doc should make it clear how the next agent proves the work. Prefer explicit commands and expected evidence over descriptive confidence.

### Priority 3: Reduce Duplicate Instruction Surfaces

Where intent, review, or triage artifacts repeat policy already present elsewhere, keep the canonical policy and remove or archive the duplicate. Where they reveal a missing policy, add the policy once in the correct owner.

### Priority 4: Strengthen Skill Lifecycle Clarity

Skill authoring, improving, proving, installing, folding, and syncing should remain understandable as one lifecycle. The docs should make it clear when to use skills, when to edit canonical skill sources, and how to validate changes.

## What This Direction Rules Out

This direction avoids creating another long-lived artifact pile beside the existing docs. Strategy should be used to clarify the docs and implementation queue, not compete with them.

It also avoids treating runtime projections as strategic source material. Projections can reveal drift or validation failures, but durable decisions belong in canonical sources.

## Decision Standard

A proposed change aligns with this strategy when it satisfies all of the following:

1. It edits the canonical source for the behavior being changed.
2. It improves agent or human ability to act without rediscovering context.
3. It has an explicit validation path.
4. It reduces contradiction, duplication, or ambiguity.
5. It preserves the repo’s operating contract and ownership boundaries.
