**Recommended Process**

For a proposed model, I’d make the call in this order:

1. **Identify the nouns.**
   List the new/changed terms. If they describe repo-wide things like skill, projection, policy, sync, validation, proof, operator doc, workflow, control plane, or canonical source, assume core until proven otherwise.

2. **Trace the blast radius.**
   Search where the current terms appear. If the terms cross `Docs/agents`, skill docs, CLI help/output, schemas, tests, or runtime projections, the model is strategic.

3. **Check ownership.**
   If the change tells agents where to edit, what is canonical, or what should be generated, it is core strategy because it affects behavior.

4. **Check command contract impact.**
   If `./bin/ask ... --json --robot` output, explanations, proofs, closeout, or validation evidence would use the model, it belongs in core strategy.

5. **Decide persistence.**
   If this is a term future agents should preserve and reuse, put it in core strategy. If it is just a local cleanup to make a page read better, keep it local.
