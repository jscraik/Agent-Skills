# Strategic Direction

## Purpose

This document compresses the current intent, review, and triage artifacts into a durable direction for Agent Skills Kit. It is meant to guide future implementation, cleanup, validation, and documentation decisions without requiring agents to rediscover the same priorities from scattered notes.

## Strategic Thesis

Agent Skills Kit should function as the canonical control plane for authoring, validating, discovering, and syncing Codex skills, operator docs, and agent workflows. The system should optimize for clear source ownership, predictable robot-facing operations, durable validation evidence, and low-ambiguity agent execution.

The direction is to reduce instruction sprawl, preserve canonical sources, make generated/runtime projections visibly subordinate, and keep workflows explainable through repo-native commands.

## Durable Principles

1. Canonical sources come first.
   Agents and humans should edit the owned source of truth, not generated runtime projections. Projection paths should be treated as outputs unless ownership documentation explicitly says otherwise.

2. Repo wrappers define the operating surface.
   Root-level work should go through `./bin/ask` and its robot-readable modes. Package-manager commands should only run inside verified package roots.

3. Agent-facing guidance should be compact, current, and scoped.
   Guidance should tell agents what to do, where to start, and which command proves the result. Stale, duplicated, contradictory, or overly narrative instructions should be removed or folded into canonical docs.

4. Validation evidence should be explicit.
   Closeout should report exact commands, pass/fail status, changed files, and any unvalidated risk. “Looks good” is not a validation result.

5. Runtime projections should be reproducible.
   Generated skill/runtime surfaces should be derivable from canonical inputs, with sync behavior and drift handling made obvious.

6. Triage should become direction, not backlog noise.
   Review and triage artifacts should be compressed into decisions, constraints, and next actions. Once absorbed, the original artifact should either be archived, linked as evidence, or deleted if obsolete.

3. Normalize robot-readable workflows.
