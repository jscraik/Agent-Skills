**Acceptance Criteria**

- Standard work records a gate-selection decision before closeout.
- The record names each selected validation gate and classifies it as `minimum proof`, `focused gate`, or `heavy gate`.
- Minimum proof is always recorded for standard work, even when broader validation is intentionally skipped.
- Minimum proof includes the smallest relevant evidence that the change was exercised, such as a targeted test, lint check, smoke command, dry run, generated artifact check, or explicit manual inspection note.
- When a heavy gate is skipped, the work record captures:
  - the skipped gate name,
  - the reason it was skipped,
  - the risk accepted by skipping it,
  - the smaller proof that was run instead.
- Heavy gates are only skipped when the change scope is narrow, low-risk, and covered by a smaller relevant proof.
- Heavy gates are not skipped for changes that touch shared contracts, validation tooling, release paths, security-sensitive behavior, runtime projections, or cross-repo/canonical automation unless the skip reason is explicitly approved or documented as blocked.
- A skipped heavy gate must be distinguishable from an unavailable or failing gate.
- If a gate cannot run because of environment, credentials, permissions, network, or tooling failure, the record marks it as `blocked`, not `skipped`.
- Blocked gates include the exact command attempted and the exact failure string or blocker reason.
- The closeout summary includes enough gate-selection evidence for a reviewer to understand why the selected proof was sufficient.
- The implementation is not considered accepted if the work record only says validation was “not needed” without naming the skipped gate and replacement proof.
- The implementation is not considered accepted if a heavy gate is skipped silently.
- The implementation is accepted when a standard work record shows:
  - selected minimum proof passed,
  - any skipped heavy gates are explicitly justified,
  - any blocked gates are separately classified with exact blocker evidence,
  - the final closeout clearly separates `passed`, `skipped`, and `blocked` validation outcomes.

- [ ] Minimum proof includes the smallest relevant evidence that the change was exercised.
- [ ] Skipped heavy gates record the gate name, skip reason, accepted risk, and smaller proof run instead.
- [ ] Blocked gates are recorded separately from skipped gates, with the exact command and failure string.
- [ ] Heavy gates are not skipped silently.
- [ ] Heavy gates are not skipped for shared contracts, validation tooling, release paths, security-sensitive behavior, runtime projections, or cross-repo/canonical automation unless explicitly approved or documented as blocked.
- [ ] Closeout separates `passed`, `skipped`, and `blocked` validation outcomes.
- [ ] Work is not accepted when validation is summarized only as “not needed” without gate-selection evidence.
