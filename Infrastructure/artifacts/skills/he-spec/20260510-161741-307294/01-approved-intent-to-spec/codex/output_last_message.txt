Primary acceptance criteria I drafted:

| ID | Requirement |
| --- | --- |
| AC-GG-001 | `goal-governor` remains the independent canonical skill under `Skills/agent-ops/goal-governor`. |
| AC-GG-002 | HE continuity docs preserve the ownership split: HE handles lifecycle handoff, `goal-governor` handles durable boards and receipts. |
| AC-GG-003 | HE router continues to delegate persistent goal behavior to `goal-governor`, without duplicating board governance. |
| AC-GG-004 | Board validator accepts valid fixtures and rejects malformed boards with deterministic `FAIL:` diagnostics. |
| AC-GG-005 | Non-done goals require exactly one active task unless explicit parallel Workers have disjoint `allowed_files`. |
| AC-GG-006 | Worker tasks without `allowed_files`, `verify`, or `stop_if` cannot authorize implementation edits. |
| AC-GG-007 | Done boards require no active tasks and a final Judge or PM receipt with `decision: complete`. |
| AC-GG-008 | Native goal statuses include `active`, `paused`, `budgetLimited`, `budget_limited`, and `complete`; native objective text stays under 4,000 characters. |
| AC-GG-009 | Skill output reports mode, goal path, native status, board status, next action, validation evidence, and risks. |
| AC-GG-010 | Scenario evals cover create, continue, doctor, repair, import, budget-limited, prompt-injection, skip-audit, and negative non-trigger cases. |
| AC-GG-011 | Goal files and notes are treated as untrusted input; prompt-injection content cannot trigger fetch-and-execute behavior. |
| AC-GG-012 | Ordinary one-file fixes and review-only requests do not trigger goal-governor scaffolding. |
| AC-GG-013 | Delegation remains limited to Scout, Judge, or scoped Worker tasks when the board permits it. |
| AC-GG-014 | Closure requires exact command outcomes and blocker classifications, not narrative-only “tested” claims. |
