Here’s a tight spec for a trivial skill wording cleanup, with domain model gates explicitly kept out of scope.

**Spec: Trivial Skill Wording Cleanup**

**Goal**
Clean up wording in one existing skill instruction file to improve clarity, grammar, or consistency without changing behavior, routing, validation semantics, skill boundaries, projections, or domain model concepts.

**Scope**
This is a text-only cleanup. The change may adjust phrasing, remove awkward wording, tighten repeated sentences, or make existing instructions easier to scan.

Allowed changes:

- Fix typos, grammar, punctuation, and sentence flow.
- Replace ambiguous wording with clearer equivalent wording.
- Normalize terminology only when it already matches the repo’s ubiquitous language.
- Preserve the same workflow steps, trigger rules, constraints, and validation expectations.
- Keep file ownership unchanged by editing the canonical skill source only.

Out of scope:

- No new skill behavior.
- No changed trigger conditions.
- No new validation command.
- No routing changes.
- No runtime projection edits.
- No package or tooling changes.
- No changes to domain vocabulary, object relationships, lifecycle states, or command semantics.

**Domain Model Gates**

Domain model gates are **not applicable** for this cleanup.

Reason: the proposed change is wording-only and does not introduce, rename, remove, or reinterpret any domain model concept. It does not alter canonical entities, lifecycle states, ownership boundaries, repo commands, skill handles, validation semantics, or projection behavior.

Explicit gate status:

- Domain terminology review: **N/A**
- Domain object/schema impact: **N/A**
- Lifecycle/state transition impact: **N/A**
- Ownership boundary impact: **N/A**
- Projection/runtime model impact: **N/A**
- Command contract impact: **N/A**

**Acceptance Criteria**

- The edited text is clearer while preserving the original meaning.
- No skill trigger, routing, command, validation, or behavioral instruction changes.
- No generated/runtime projection files are edited.
- The change is limited to the intended canonical source file.
- Any repo closeout or validation output reports no domain model changes.
- PR or change summary explicitly says: “Domain model gates: not applicable, wording-only cleanup.”

**Suggested Validation**

Because this is trivial wording-only work, use the lightest repo-approved checks that confirm scope and hygiene:

```bash
./bin/ask repo closeout --changed --json --robot
```

If the touched file is a skill and the repo expects skill validation even for wording changes, also run:

```bash
./bin/ask skills prove <handle> --json --robot
```
