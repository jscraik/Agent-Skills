**Parent Issue**
Title: `Coordinate refactor program for canonical skills and agent docs`

Description:

```markdown
## Goal

Coordinate the refactor program so Agent Skills Kit has clearer canonical sources, fewer contradictory instructions, and stronger validation around skill and agent-facing documentation changes.

## Why

The repo is the control plane for authoring, validating, discovering, and syncing Codex skills, operator docs, and agent workflows. The refactor should reduce drift between canonical sources and runtime projections, make path ownership obvious, and ensure future agents can safely modify the right files with reliable proof commands.

## Success Criteria

- Canonical source boundaries are documented and reflected in active guidance.
- Stale or contradictory instructions are identified and removed or reconciled.
- Skill-facing docs use the repo’s ubiquitous language consistently.
- Validation commands provide clear pass/fail evidence for changed areas.
- Runtime projections are not edited directly as part of the cleanup.
- Closeout evidence can be produced through repo wrappers.

## Suggested Child Issues

1. Audit refactor scope against canonical language and ownership boundaries
2. Reconcile stale or contradictory agent instructions
3. Tighten skill management guidance and line-budget rules
4. Verify runtime projection boundaries and update references
5. Improve validation evidence for skill/doc changes
6. Run closeout and capture remaining follow-up work

## Validation

Use repo wrappers from the root where applicable:

- `./bin/ask repo doctor --json --robot`
- `./bin/ask skills explain <handle> --json --robot`
- `./bin/ask skills prove <handle> --json --robot`
- `./bin/ask repo closeout --changed --json --robot`
```
