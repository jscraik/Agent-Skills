**Goal:** Reduce drift between canonical skill/operator sources, runtime projections, and agent-facing docs while preserving existing repo command contracts.

**Parent Issue**

**Title:** Refactor skills control plane around canonical ownership and validation

**Type:** Parent issue / initiative issue

**Description:**

Refactor the agent-skills control plane so skill sources, operator docs, sync policy, and runtime projections follow the repository’s canonical ownership model.

This work should follow the repo operating contract:

- Use `./bin/ask` for repo operations.
- Read `UBIQUITOUS_LANGUAGE.md` before changing skills, sync policy, runtime projections, or agent-facing docs.
- Edit canonical sources rather than runtime projections.
- Validate through repo wrappers and capture robot-mode evidence.
- Keep slices small and avoid unrelated cleanup.

**Outcome:**

By the end of this parent issue, the refactor program should leave the repo easier for agents to navigate, safer to modify, and less likely to accumulate stale duplicated instructions.

**Acceptance Criteria:**

- Refactor scope is decomposed into child issues with explicit touched areas.
- Each child issue names the canonical source paths it expects to modify.
- Each child issue includes validation commands.
- No child issue requires editing runtime projections directly unless the issue explicitly proves that path is canonical.
- Closeout evidence can be produced with `./bin/ask repo closeout --changed --json --robot`.
