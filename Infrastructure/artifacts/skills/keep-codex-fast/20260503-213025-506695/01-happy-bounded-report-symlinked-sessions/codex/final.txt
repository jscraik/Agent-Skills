The bloated parts, based on the `keep-codex-fast` contract, are the Codex local-state buckets that actually grow over time:

- `sessions` and especially old, non-pinned active sessions
- `archived_sessions`
- `worktrees`, especially stale ones
- `logs_2.sqlite*`
- dead or temp project entries in `config.toml`
- heavy Node/dev processes

Your `ExternalSSD` symlink is not the bloat by itself. The bloat is the data underneath it, mainly big session history and log/worktree payloads. The skill’s own smoke test also confirms it handles symlinked session roots correctly, so the aliasing itself is expected. If the SSD is slower than internal storage, that can add latency, but the big win is still reducing session/log/worktree volume.

I could not run a live local measurement from this chat because shell access is blocked here, so this is the skill-defined bloat map rather than a current size readout. If you want the exact current offenders, the report-only command is `python scripts/keep_codex_fast.py --details`, and it will show the largest sessions, worktree candidates, log size, and config prune candidates without deleting anything.
