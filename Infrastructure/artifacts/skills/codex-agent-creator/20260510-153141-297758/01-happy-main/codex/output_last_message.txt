For validating a Codex custom subagent TOML, the exact inputs I need are:

- `user request`
- `target repo or artifact`
- `intended scope`
- `canonical source path`
- `evidence source` for edits or contract checks, such as:
  - files
  - diffs
  - issues
  - local schema
  - official docs
  - existing agents
  - validator output

Optional, if you already know them:

- `model preferences`
- `reasoning effort`
- `sandbox posture`
- `approval posture`
- `nickname candidates`
- `safety constraints`
- `privacy constraints`

If the TOML is standalone or discoverability-linked, I may also need:

- the role file itself or its path
- the declaring config path, if it is referenced via `[agents.<name>].config_file`
- the intended scope, such as validation-only, global, project, or repo-owned
- the validation goal, such as syntax only, schema/field contract, discoverability, runtime posture, or full role validation
