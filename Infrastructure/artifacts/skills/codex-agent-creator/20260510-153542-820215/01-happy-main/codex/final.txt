     - `.agents/subagents/<name>.toml`

   - The canonical name users or tooling should invoke.

   - Pick one:
     - **Schema validation only:** check required keys, field types, invalid TOML, duplicate keys.

     - **Behavioral validation:** schema plus whether the prompt/tools/model/permissions actually fit the intended role.
     - **Release-ready validation:** all of the above, plus evidence commands and closeout checks.

   - If you have a reference subagent TOML, send its path or contents.

   - What the subagent is supposed to do.
   - What it must not do.
   - Whether it should have tools, filesystem access, network access, MCP access, or delegation ability.

8. **Model and reasoning expectations**
   - The intended model, if fixed.
   - Whether reasoning effort is required or should be omitted.

9. **Prompt requirements**
   - Any required system/developer-style instructions.
   - Required tone, review rubric, escalation rules, output format, or safety constraints.

10. **Validation mode**
   - Whether you want:
     - a concise pass/fail report,
     - a detailed findings list,
     - suggested fixes without editing,
     - or a patch plan for later.
