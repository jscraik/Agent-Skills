I audited `spec-driven-development`, `using-agent-skills`, and `planning-and-task-breakdown` with a strict Plugin Eval-style pass. I couldn’t apply the edits in this session because the local workspace path isn’t mounted here, so the repo itself remains unchanged.

**Findings**
- `using-agent-skills` is too underspecified when multiple skills match. The routing tree is good, but it doesn’t define a deterministic tie-breaker for ambiguous work, so an agent can over-select `spec-driven-development` when `debugging-and-error-recovery`, `test-driven-development`, or `incremental-implementation` is the better fit. See [using-agent-skills/SKILL.md](https://github.com/addyosmani/agent-skills/blob/main/skills/using-agent-skills/SKILL.md#L248-L350).
- `spec-driven-development` uses a hard “30 minutes” trigger, which is brittle and can misclassify both short high-risk work and longer-but-obvious changes. A more stable threshold is “more than one focused session” or “more than one dependent step,” which keeps the intent without overfitting to time. It also benefits from an explicit phase-handoff rule so the plan and task breakdown stay anchored to the spec’s objective and success criteria. See [spec-driven-development/SKILL.md](https://github.com/addyosmani/agent-skills/blob/main/skills/spec-driven-development/SKILL.md#L246-L264).
- `planning-and-task-breakdown` has strong task scaffolding, but it does not require traceability from each task back to a spec objective, success criterion, or open question. That makes it easier for a plan to drift into “reasonable work” instead of “the work we actually agreed to.” See [planning-and-task-breakdown/SKILL.md](https://github.com/addyosmani/agent-skills/blob/main/skills/planning-and-task-breakdown/SKILL.md#L305-L341).

**Regression Control**
- Keep the skill names, ordering, and top-level workflow unchanged.
- Only adjust routing clarity, threshold wording, and task/spec traceability.
- Do not broaden any trigger scope.
- Do not add new workflow phases.

**What I would change**
- In `using-agent-skills`, add one tie-breaker rule: choose the narrowest skill for the current phase, with a short precedence example set.
- In `spec-driven-development`, replace the 30-minute cutoff with a session/complexity-based trigger and add a line that each handoff must preserve the spec’s objective and success criteria.
- In `planning-and-task-breakdown`, add a `Traceability` field to the task template so each task explicitly maps back to the spec.
