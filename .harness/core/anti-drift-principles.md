# Anti-Drift Principles

Purpose: identify architectural decay early.

## Drift Indicators

- Command modules grow instead of service boundaries emerging.
- Prompt or docs grow without eval or command-output improvement.
- More than one first-action path appears.
- Skills overlap without routing proof.
- Generated/runtime surfaces lack ownership.
- Catalog parity blocks or becomes ignored.
- Historical artifacts enter primary browsing paths.
- Governance checks lack owner or proof target.
- Compatibility paths lack expiry.
- Linear work becomes one issue per finding.

## Anti-Entropy Rules

- Convert repeated failures into commands, validators, evals, or memory.
- Classify before deleting; do not preserve unclassified sprawl.
- Keep proof labels explicit.
- Block new default-visible skills without proof status.
- Block new unclassified generated/runtime artifacts.
- Block new feature logic in overgrown command modules unless it is extraction work.
- Add no orchestration layer without measurable leverage.

## Early Warning Thresholds

- Rising context load with no reliability gain.
- New command paths bypass the golden path.
- New governance gates duplicate existing proof.
- Agents need multiple docs to determine safe next action.
- Generated files require human interpretation to know editability.
