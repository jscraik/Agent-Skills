Purpose

Implement JSC-364 by adding a Codex Runtime Proof Plane to Agent Skills Kit. The proof plane must make ./bin/ask produce durable runtime proof or durable blocked_runtime evidence for Codex-targeted checks.

The core trust boundary is that modeled Codex compatibility, generated projection readiness, docs, plans, and local intent must not be reported as live runtime proof.

Deep Modules

The JSC-364 implementation should behave like a small set of deep modules: each module owns a narrow public surface, hides its internal mechanics, and exports evidence that another agent can verify without reading private context.

Architecture decision: this work should extend the project's current deep modules, not create a parallel proof framework. Command modules should orchestrate public ./bin/ask behavior; command_surface.py, skills_sdk/runtime_adapters.py, skills_sdk/conformance.py, services/codex_preview.py, and schema validators should own the durable behavior.

Runtime Proof Plane

This is the main deep module. Its public promise is simple: given a skill handle and runtime target, return proof or durable blocked_runtime evidence.

  • Owns RuntimeCard and proof result assembly.
  • Separates modeled conformance from live runtime parity.
  • Reports source identity, artifact paths, blocker class, and next operator command.
  • Hides probe sequencing, runtime availability checks, and evidence writing details.

Governed Slice Loop

This module keeps work bounded and reviewable. It does not prove runtime truth itself; it decides when a slice is safe to start, commit, hand to PR triage, or stop.

  • Goal board state and receipts.
  • Allowed files and stop conditions.
  • Simplify, unslopify, HE code review, testing, adversarial, and agent-native review gates.

Command Surface

The CLI is the stable front door. Agents should call public ./bin/ask commands, not private helpers.

  • skills handles blocks drift.
  • repo doctor names the next command.
  • skills proof emits runtime-targeted evidence.

Evidence Schemas

Schemas make proof durable. The validator rejects missing runtime target, source identity, command, artifact visibility, or blocker fields.

  • RuntimeCard
  • EvidenceReceipt
  • ArtifactRecord
  • RuntimeSessionSummary
  • RecoveryPlanSummary

Workspace Evidence

Artifacts live in repo-owned paths so another agent can find and verify them later. This prevents a private session summary from becoming the only proof.

  • Evidence receipts under .harness/evidence or explicit test paths.
  • Review artifacts under artifacts/reviews.
  • Implementation notes here.

Delivery Truth

PR, CI, review, and Linear truth stay separate from local proof and must be refreshed before delivery claims.
