# Learnings

- **2026-04-08 [Codex]:** 1Password-backed SSH/Git flows can fail in login-shell automation with `Could not open a connection to your authentication agent` when `SSH_AUTH_SOCK` is only exported in `.zshrc`. Fix by exporting the 1Password socket in `.zprofile` (and keeping `.zshrc` aligned), then validate with `zsh -lc "ssh-add -l"` and `ssh -T git@github.com`. GitHub SSH auth often exits with code `1`; treat the success banner as the signal.
- **2026-04-08 [Codex]:** Codex sessions can sometimes force `Approval policy is currently never` despite local `on-request` or `on-failure` config, which triggers `AskForApproval is set to Never` rejections. Workaround: relaunch with explicit flags and confirm with `codex debug prompt-input "policy check"`.
- **2026-04-12 [Codex]:** Plugin visibility outages in `~/.codex-red` were caused by cache layout drift: Codex loads plugins from `~/.codex-red/plugins/cache/<marketplace>/<plugin>`, but cache content had been nested under `local/` or `<version|sha>/`, leading to `failed to load plugin: plugin is not installed`.
- **2026-04-12 [Codex]:** Flat projection remains required for picker reliability in this environment. Keep plugin-authorized skills surfaced in `.agents/skills` so enabled plugin families remain visible by default.
- **2026-04-12 [Codex]:** Duplicate protection for homes like `~/.codex-red` is cache-layout hygiene, not flat-skill suppression. Flatten cache roots and audit overlap via `scripts/check_codex_home_skill_overlap.sh --strict --show-overlap` (optionally with `--remediate-cache-skills` to repair nested cache layouts).
- **2026-04-12 [Codex]:** Validation contract for this incident class: `bash scripts/sync_skills.sh`, `bash scripts/check_plugin_skill_shadowing.sh`, `uv run --python 3.12 -m unittest scripts/test_skill_lifecycle_validation.py`, and `PATH_OWNERSHIP_ALLOW_CACHE_WRITES=1 bash scripts/verify-work.sh` (use `--workspace-governance` only for explicit workspace/home scope checks).
- **2026-04-12 [Codex]:** Codex profile homes also need plugin metadata projection (`plugins/marketplace.json` under `~/.codex-*/plugins/`) or picker plugin cards may disappear even when skills are present.
- **2026-04-12 [Codex]:** Profile metadata projection is not enough by itself: when `~/.codex-*/plugins` is a real directory (not a symlink), `marketplace.json` entries using `./plugins/<name>` also require profile-local plugin source mirrors at `~/.codex-*/plugins/<name>` (symlinked to canonical repo plugins) or local plugin families can disappear from picker views.
- **2026-04-12 [Codex]:** rsync cache cleanup can leave stale nested plugin versions (`0.1.0/`) unless delete runs with force semantics. Keep plugin cache sync/remediation on `rsync --delete --force` to prevent residual duplicate loaders.
- **2026-04-12 [Codex]:** Maintain a strict `.system` bridge allowlist for lifecycle entry skills only (`skill-creator`, `skill-installer`, `plugin-creator`, `plugin-installer`). Route those four through `.agents/skills/.system/*` after sync so the bridge stays explicit and bounded.
