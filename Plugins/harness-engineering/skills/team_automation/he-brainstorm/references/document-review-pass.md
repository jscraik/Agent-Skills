# Document Review Pass

Load full doctrine when needed: `Infrastructure/references/harness-engineering/he-brainstorm-doctrine.md`.

Before handoff, verify subject, audience, value, expected behavior, `mode`, `scope_tier`, `spec_required`, `risk_level`, `complexity`, traceable requirements, true planning blockers, safe deferred HOW questions, canonical domain terms, evidence-tied recommendation, and visual/prose agreement.

Red flags: next stage must invent behavior, options are unranked, assumptions are hidden as requirements, implementation detail leaks into scope, `he-plan` is recommended while a spec is required, or repo behavior is claimed without inspection.
