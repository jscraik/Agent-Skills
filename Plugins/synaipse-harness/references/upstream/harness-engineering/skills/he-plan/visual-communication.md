# Visual Communication

Read when a plan would be easier to review with a structure-level visual.

- Use dependency graphs for four or more non-linear plan units.
- Use interaction or component diagrams when system impact spans three or more surfaces.
- Use comparison tables for modes, variants, decisions, or alternatives.
- Keep visuals at plan-structure level. Do not encode method names, SQL, API fields, or implementation architecture unless the plan explicitly needs a directional technical design.
- Prose is authoritative if a visual and text disagree.
