Product Boundary

The atlas starts by separating the repo that incubates skills from the SDK contract that professionalizes them, the Tessl surfaces that distribute/prove them, and the local runtime that reveals whether installation actually works.

Product rule: Skills Foundry retains source; agent-skills implements and dogfoods the SDK for selected candidates. Tessl is distribution/proof. Local runtime is behavior truth.

Canonical Pipeline

The SDK lifecycle is a repeated control cycle, not one early box. Each security or proof lane returns to the SDK before the package advances.

Order is a contract: security review precedes local proof, local proof precedes cloud proof, Tessl dry run precedes external Tessl evaluation, and runtime feedback returns to the Foundry. Behavioral release proof uses one 5-to-10-case scenario set, targets 8, and preserves the exact case ids across both OSS lanes and Tessl.

Author-Facing Golden Path

This is the surface a skill author should see. Everything else is behind progressive disclosure.

Do not expose the full atlas as the default user journey.
1Create / choose templateStart from minimal, scripted, plugin, or governed skill template with a default risk tier.
2Edit SKILL.mdKeep instructions compact. Move contracts and provenance into references or companion files.
3Run ask sdk checkReport tier, blockers, next action, evidence, and skipped heavyweight checks.
4Preview / installPreview target paths, then apply only to explicit marked project roots.
5Review routeSelect lenses, create review plan, create handoff, execute local artifacts, verify required artifacts.
6Eval runRun deterministic local evals or internal skill evals; target-bound receipts carry package identity and case counts. A/B execution should use Codex sandbox modes via codex exec.
7Sign / quarantineSigning intent is local and ready; directory-form external skill intake now emits quarantine receipts, and eval execution uses Codex sandbox modes.
8Publish / registryNot V1. Do not expose until real signatures, release trust policy, evals, and package identity are ready together.
