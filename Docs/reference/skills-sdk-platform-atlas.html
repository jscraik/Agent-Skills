Skills SDK Platform Atlas

Truth-aware edition. This artifact separates what the current SDK actually proves from the north-star platform: compiler, emitters, signing, sandboxing, evals, trust, registry, CI, and hosted distribution.

Security Intake Backlog

Tal-derived defensive review lanes for treating skills as dependency-like operational inputs with provenance, permissions, data exposure, sandboxing, semantic behavior, and approval friction checks.

Security rule: do not claim third-party skill safety until intake, runtime, and approval receipts prove the exact lane being discussed.
provenanceSkill Intake Security ReviewRecord source, owner, maintainer, version, purpose, repo history, release notes, and adoption decision before external or plugin skills become active runtime inputs.
permissionsPermission Delta ReviewCompare install or update plans for new filesystem, network, shell, browser, API, secret, and write access before approval.
dataData Exposure ReviewClassify model-visible prompts, retrieved files, tool outputs, logs, transcripts, and secret-handling boundaries for each skill package.
actionsAction Surface ReviewList irreversible or high-impact actions a skill can cause, including writes, installs, publishes, messages, tickets, browser actions, and external API calls.
isolationThird-Party Skill QuarantineInspect, package, eval, and harden untrusted skills in a staged lane before installation, runtime projection, or user-level exposure.
semanticSemantic Security ReviewReview what the skill can instruct the agent to do, not only filenames, frontmatter, regex hits, or package formatting.
approvalApproval Friction PolicyDefine when the SDK blocks, warns, asks, or auto-allows so human review remains meaningful without training operators to ignore prompts.

Author-Facing Golden Path

This is the surface a skill author should see. Everything else is behind progressive disclosure.

Do not expose the full atlas as the default user journey.
1Create / choose templateStart from minimal, scripted, plugin, or governed skill template with a default risk tier.
2Edit SKILL.mdKeep instructions compact. Move contracts and provenance into references or companion files.
3Run ask sdk checkReport tier, blockers, next action, evidence, and skipped heavyweight checks.
4Preview / installPreview target paths, then apply only to explicit marked project roots.
5Review routeSelect lenses, create review plan, create handoff, execute local artifacts, verify required artifacts.
6Eval runRun deterministic local evals or internal skill evals; target-bound receipts carry package identity and case counts.
7Sign / sandboxSigning intent is local and ready; real signatures and sandbox execution stay blocked until adapters and policies exist.
8Publish / registryNot V1. Do not expose until real signatures, release trust policy, evals, and package identity are ready together.
