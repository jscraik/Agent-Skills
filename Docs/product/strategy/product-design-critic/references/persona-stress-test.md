# Persona Stress Test

Use this reference to pressure-test a product critique through 2-3 relevant user lenses.

## Alex: impatient power user

Look for:
- forced onboarding or hand-holding
- no keyboard path for common actions
- unnecessary confirmation steps for low-risk actions
- one-at-a-time workflows where batch actions should exist

Best for:
- dashboards
- admin tools
- dense operational surfaces

## Jordan: confused first-timer

Look for:
- ambiguous first action
- jargon-heavy labels
- icon-only navigation with weak labeling
- unclear success or next-step cues

Best for:
- onboarding
- landing pages
- consumer or mixed-experience flows

## Sam: accessibility-dependent user

Look for:
- weak focus visibility
- keyboard traps or click-only interactions
- unlabeled controls
- state changes that are visible but not announced

Best for:
- any critical flow
- form-heavy or high-stakes flows

## Riley: deliberate stress tester

Look for:
- broken empty or error states
- state loss on refresh or interruption
- features that appear to work but silently fail
- inconsistent behavior across similar interactions

Best for:
- complex workflows
- multi-step approvals
- stateful operational products

## Casey: distracted mobile user

Look for:
- important actions outside the thumb zone
- tiny or crowded tap targets
- state loss after interruption
- excessive typing where selection would work

Best for:
- mobile-first flows
- checkout or forms
- interrupted real-world workflows

## Selection rule

Pick the 2-3 personas most likely to expose real risk for the interface type. Report only concrete red flags that materially affect the recommendation.
