# Improvement Rubric

Use this rubric to evaluate candidate ideas before keeping them.

## Score each idea on 1-5

- `user_value`: Does this materially improve the user experience or outcome?
- `agent_value`: Does this make the system easier for AI agents to understand, use, extend, or operate safely?
- `differentiation`: Does this make the project feel more distinctive or compelling?
- `implementation_cost`: Is the cost acceptable relative to the upside?
- `complexity_burden`: Does it avoid adding disproportionate operational or cognitive overhead?
- `reliability_impact`: Does it improve trust, safety, observability, or robustness?
- `adoption_likelihood`: Will people actually use or benefit from it?
- `reversibility`: Can it be rolled back or staged if it underperforms?
- `evidence_fit`: Does it match the real constraints and shape of the current project?

## Hard rejection criteria

Reject the idea if any of these are true:
- it is impressive-sounding but weakly connected to the project's actual problems
- it adds a lot of code, UI, or maintenance burden for marginal benefit
- it depends on speculative infrastructure, partnerships, or data the project does not have
- it duplicates existing behavior without a meaningful leap in usefulness
- it makes the product harder to learn, explain, or operate
- it is difficult to stage, test, or roll back

## Keep criteria

Prefer ideas that:
- create obvious user benefit quickly
- improve both human and agent workflows
- tighten feedback loops or trust signals
- simplify the product while making it feel more capable
- can be implemented incrementally

## Suggested shortlist buckets

- `quick win`: strong gain, low complexity
- `high leverage`: meaningful gain with moderate complexity and strong strategic value
- `strategic bet`: higher uncertainty, but worth it if the upside is unusually strong
