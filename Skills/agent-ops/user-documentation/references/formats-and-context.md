## Dashboards and reports

Document the configured report and intended user's access, not generic platform
capabilities. Check navigation, active filters, resets, empty results, dates/units
and visible freshness. Distinguish viewing, filtering and changing source records.
An empty result need not mean absence; a slicer need not change stored data.
Include export, drill-through or mobile behaviour only when confirmed. Keep
report development and database administration outside the user guide.

## Office and delivered exports

Word: preserve styles, numbering, captions, links, tables, fields, comments and
revisions. Use tracked changes only when requested and supported; ordinary edits
are not tracked changes. PowerPoint: distinguish standalone walkthroughs from
demo slides; essential instructions must reach users, not remain only in notes.
Excel: edit authorised explanatory text only; preserve formulas, values, identifiers,
validation and workbook behaviour.

Use the appropriate document tool skill when available. Without editing support,
return located replacement text. Read back applied changes. Inspect exports for
readable images, complete content, page breaks, wrapped tables and usable links
when possible. A saved source does not prove its PDF or exported hidden content.

## Online guides and changing features

GitBook is an optional destination, not a required dependency. When requested,
use the installed GitBook connector's supported tools; inspect the actual space,
pages, permissions and authoring flow first. Use native headings, lists, callouts,
tabs or reusable content only where current tools and destination support them.
Never invent GitBook tool names or markup. Preserve page links, assets and sidebar
order, and verify saved content and reader preview when available. If the connector
is absent or lacks editing/preview access, provide located replacement Markdown
without claiming it was saved. Publishing, sharing and access changes still need
explicit authority. Do not request access tokens in chat.

Inspect navigation and authoring ownership. Preserve links/assets; check intended
reader access, not merely the current signed-in account. Verify resolved includes,
variables, moved-page links and redirects where relevant. Use maintained reuse
when available, not new machinery for a small guide. Explain verified renamed
or withdrawn features and supported alternatives. Wording edits are not renewed
product verification. Keep edits, sync, preview and publication separate: do not
invent preview links, publish, share or change access without explicit authority.
