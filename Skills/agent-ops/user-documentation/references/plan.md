# User Documentation Build Plan

## First-principles decision

- Outcome: non-technical end users can onboard and use the actual software.
- Decision: BUILD_SKILL. Its audience and task procedure differ from
  technical-writer's developer, administrator and operator documentation.
- Rejected assumption: copying a long Word template or entire capsule collection
  proves usefulness. Keep a compact entrypoint and two focused references.
- Constraints: verified UI/version/role, privacy, no implied product mutation or
  publication, self-contained references and bounded validation.
- Mechanism: one instruction-only skill, no scripts, services or dependencies.
- Proof: strict audit, package closure, realistic boundary cases, discovery and
  complete runtime comparison. Actual model efficacy is a separate proof lane.
- Stop/pivot: report missing UI evidence or installation capability; do not call
  source validation activation or registry clearance.

Primary source: Jamie's supplied `User Documentation Skill.docx`, received

Private source paths are not runtime dependencies.

Adaptations are contained in `user-guide-quality.md`, not sibling runtime links.

API, command or registry machinery was copied. Technical Writer retains the
originals: readability and accessibility also help technical readers. Jamie owns
the adaptations. Compare relevant source changes rather than silently syncing
