## Principles

### principle.evals.failure-taxonomy-before-automation: Failure Taxonomy Before Automation

- Type: principle
- Status: reviewed
- Claim strength: synthesized
- Source boundaries: local_source_reference
- Derived from claims: claim.evals.traces-before-evals, claim.evals.error-analysis-before-judges, claim.evals.dimensions-sample-user-space, claim.evals.measurement-supports-decisions

Build evals from observed failure modes, not from generic quality labels.

Rationale: A judge or dashboard is only useful after trace review has surfaced specific, repeated, product-relevant failures and the decision the evidence should inform.

Application notes:
- Ask for traces, artifacts, or representative examples before designing an evaluator.
- Ask what decision this measurement will change.
- Name dimensions and failure categories before choosing metrics.
- Prefer a small set of actionable failure labels over a broad helpfulness score.

## Checklists

### checklist.evals.trace-error-analysis: Trace Error Analysis Checklist

- Type: checklist
- Status: reviewed
- Claim strength: synthesized
- Source boundaries: local_source_reference
- Derived from claims: claim.evals.traces-before-evals, claim.evals.error-analysis-before-judges, claim.evals.dimensions-sample-user-space, claim.evals.measurement-supports-decisions, claim.evals.testing-models-can-be-flawed, claim.evals.intuition-needs-observable-justification, claim.evals.exploration-is-sampling, claim.evals.abduction-guides-test-investigation, claim.evals.coverage-is-multidimensional

- [ ] State the decision, risk, or product goal the eval evidence should inform.
- [ ] Name the model, oracle, or expected-behavior source behind the test.
- [ ] Confirm traces or equivalent artifacts capture inputs, outputs, tool calls, model/prompt version, and relevant context.
- [ ] Define product-relevant dimensions before sampling examples.
- [ ] Review a bounded trace sample and write short failure notes.
- [ ] Group notes into specific, reusable failure categories.
- [ ] Convert strong intuition into an observable claim before using it as evidence.
- [ ] Count frequency and record severity separately.
- [ ] Record which coverage dimensions were sampled and which remain unknown.
- [ ] Select the first evaluator from the most important repeated failure, not from a generic quality label.
- [ ] Turn each unexplained failure into a hypothesis and gather corroborating or refuting evidence.
- [ ] Record unresolved coverage gaps and the next sample needed.

### lens.evals.testing-proof-selection: Testing Proof Selection Lens

- Type: lens
- Status: reviewed
- Claim strength: synthesized
- Source boundaries: local_source_reference
- Derived from claims: claim.evals.traces-before-evals, claim.evals.code-evals-are-deterministic, claim.evals.judge-validation-needs-tpr-tnr, claim.evals.evals-close-loop, claim.evals.production-needs-online-guardrails, claim.evals.measurement-supports-decisions, claim.evals.experiments-need-valid-metrics, claim.evals.productivity-requires-goal, claim.evals.testing-models-can-be-flawed, claim.evals.intuition-needs-observable-justification, claim.evals.exploration-is-sampling, claim.evals.abduction-guides-test-investigation, claim.evals.coverage-is-multidimensional

- Tie every proof path to the decision, risk, or goal it is meant to inform.
- Name the model, oracle, or expectation the test is using and what it cannot see.
- Start by asking what observed failure or behavior claim needs proof.
- Treat intuition as a lead; require observable evidence before closeout.
- Prefer deterministic checks for objective properties and calibrated judges for semantic properties.
- Require traces, fixtures, or artifacts before treating eval scores as evidence.
- For experiments, name the primary metric, guardrails, randomization or sampling basis, and instrumentation.
- Report coverage by dimension and preserve caveats when the sample is incomplete.
- Separate measurement evals from online guardrails that prevent high-risk responses.
- Turn fixed failures into regression cases or record why retention would be unsafe or low-value.
