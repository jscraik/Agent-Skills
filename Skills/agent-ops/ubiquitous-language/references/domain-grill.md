# Domain Grill Procedure

Use this procedure when the user asks to be grilled, challenged, interviewed
deeply, or stress-tested against the project domain model.

- Walk the design tree branch by branch until the plan, language, and decision
  boundaries are sharp enough to act on.
- Ask one question at a time and wait for the user's answer unless repository
  evidence can answer it cheaply.
- Include a recommended answer and its trade-off with each question.
- Call out conflicts with the active glossary immediately and ask which meaning
  should win.
- Propose a canonical term and aliases to avoid for vague or overloaded wording.
- Use concrete scenarios and edge cases to test adjacent concepts.
- Cross-check claims against code or docs; report contradictions as evidence.
- Capture resolved terms in the glossary as they resolve.
- Stop or hand off when the remaining uncertainty is implementation detail,
  architecture trade-off, tracker planning, or a decision-record question.
