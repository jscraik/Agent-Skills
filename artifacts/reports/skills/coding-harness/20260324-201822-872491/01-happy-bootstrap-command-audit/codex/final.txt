**Safe Order**
1. Repo preflight only: verify root, required binaries, and current harness status.
   Use the repo-approved form, not the stale sourced-shell form: `bash scripts/codex-preflight.sh --stack auto --mode required`.
2. Command truth check: inspect `harness --help` and `harness init --help`.
   This matters because some reference docs in the skill still contain older examples.
3. Non-mutating harness inspection:
   `harness --version`
   `harness init --check-updates`
   `harness init --dry-run`
   `harness check-environment --json`
4. Decide lane before any write:
   If the dry run shows normal scaffold drift only, use the update lane.
   If you want CircleCI as the target provider, use the CI-migration lane.
   If this repo should remain GitHub-Actions-based, do not run `ci-migrate`.
5. Mutating step only after preview review:
   Update lane: `harness init --update`
   Fresh re-scaffold lane only if update is not sufficient: `harness init`
   CI migration lane, only if you explicitly want CircleCI:
   `harness ci-migrate prepare --provider circleci --dry-run`
   `harness ci-migrate prepare --provider circleci --apply`
   `harness ci-migrate verify --snapshot <snapshot-id>`
   `harness ci-migrate commit --snapshot <snapshot-id>`
   Rollback path if needed: `harness ci-migrate abort --snapshot <snapshot-id>`
6. Re-run validation after whichever write path we choose.

**Needs Your Credentials**
These steps still need your credentials or explicit ownership:

- Private package install for `@brainwav/coding-harness`:
  requires `NPM_TOKEN`, often via 1Password.
- `npm whoami` / private registry reachability:
  requires valid npm auth.
- Branch protection changes:
  requires a GitHub token with the needed scopes, usually `GITHUB_PERSONAL_ACCESS_TOKEN`.
- Greptile verification:
  requires GitHub auth for repo verification, and the Greptile GitHub App must already be installed by you/org admins.
- CircleCI environment-variable inspection or setup:
  requires `CIRCLE_TOKEN`, plus manual setup of project env vars like `NPM_TOKEN`, `GITHUB_PERSONAL_ACCESS_TOKEN`, `GREPTILE_API_KEY`, and possibly `LINEAR_API_KEY`.
- Any actual secret creation or rotation:
  harness can verify presence, but it cannot mint or rotate these for you.
