For the harness, you’d usually prefer a GitHub App JWT when the question is specifically “is this app installed here, and can this installation act on this repo?” because a JWT proves the app’s identity, not a human user’s identity.

A PAT answers a different question. A PAT says “this user can access the repo,” which can mask the exact thing you’re trying to verify. If `harness verify-greptile` succeeds with a PAT, you still haven’t cleanly proven that the GitHub App installation itself is present and authorized. A GitHub App JWT is the right starting credential for installation-scoped verification, because it maps to the app, can be exchanged for an installation token, and keeps the check aligned with the actual production actor.

Why that’s better in practice:
- Least privilege: the resulting installation token is scoped to the app installation and granted permissions, instead of inheriting a user PAT’s broader repo/org reach.
- Better signal: success means “the app installation is valid for this repo,” not merely “some maintainer’s PAT can see this repo.”
- Cleaner ops: JWTs are short-lived and app-managed, so they’re safer to automate than long-lived PATs.
- Better governance: orgs often restrict PAT usage more aggressively than GitHub Apps, and app auth is easier to reason about in audits.

The nuance in this repo is that the docs are a little mixed. The harness reference explicitly says GitHub App JWT is preferred for remote GitHub checks when verifying app installation state in [utilities/coding-harness/references/setup-and-commands.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/setup-and-commands.md), but the install guide still shows PAT-based examples for `verify-greptile` and other GitHub operations in [utilities/coding-harness/references/agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md). My read is: PAT is still accepted because it’s convenient and also needed for some user-level tasks like `gh` CLI auth and branch protection, but for verifying app-installation access specifically, JWT is the more correct credential.

A simple rule of thumb:
- Use GitHub App JWT when verifying GitHub App installation state.
- Use PAT for user-operated repo/admin flows like `gh` CLI actions, branch protection, or manual maintenance steps.
