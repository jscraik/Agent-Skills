**Safe Sequence**

For a consumer repo, the safest harness setup ladder is:

1. Preflight the repo and toolchain.
   Source of truth: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [agent-install.json](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install.json), [SKILL.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/SKILL.md).
   The intended order is prerequisites first, then private package auth, then global harness install, then `harness init --dry-run`, then `harness init`, then `harness init --check-updates`.

2. If the repo already has GitHub Actions CI, do a reversible CI migration instead of hand-editing workflow files.
   Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md).
   The safe path is preview, apply, verify, commit, with `abort` available from the migration snapshot if anything looks wrong.

3. Trust and install the pinned tool baseline from `.mise.toml`, then run harness environment verification.
   Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md).
   After scaffold, the next checkpoint is the mise/tooling layer, not branch protection or remote checks.

4. Only after local scaffold and environment checks are green, move on to external systems.
   That means CircleCI env vars, branch protection, Greptile GitHub App verification, and any authz verification.
   Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [06-security-and-governance.md](/Users/jamiecraik/dev/Agent-Skills/docs/agents/06-security-and-governance.md).

5. Finish with the end-to-end validation ladder and stop on the first failing gate.
   Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [04-validation.md](/Users/jamiecraik/dev/Agent-Skills/docs/agents/04-validation.md), [structured-json-output.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/structured-json-output.md).

**Validation Gates**

The setup has three practical gate levels:

- Local baseline gates:
  `harness init --dry-run` must look correct before any writes.
  `harness init --check-updates` should report no pending scaffold drift after apply.
  `harness check-environment --json` verifies the harness/tooling baseline.
  `pnpm check` is the baseline repo policy gate.

- Deep gate:
  `pnpm test:deep` is only required when runtime behavior, contract behavior, or artifact behavior changed.
  Source: [SKILL.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/SKILL.md), [setup-and-commands.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/setup-and-commands.md).

- Conditional governance/remote gates:
  `harness verify-greptile`
  `harness check-authz`
  `harness docs-gate --json`
  `harness tooling-audit`
  `harness health --auto-fix --dry-run --json`
  These are additive, and some are blocked until credentials exist.
  Source: [SKILL.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/SKILL.md), [structured-json-output.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/structured-json-output.md).

The clean “done” claim in the harness docs is stricter than a normal local pass: all of the end-to-end steps must pass, including Greptile and authz verification, before setup is considered complete.

**What Still Needs Your Credentials**

These parts are user-owned or auth-gated and cannot be fully completed by harness alone:

- `NPM_TOKEN`
  Needed for private package access to `@brainwav/coding-harness`, and also as a CircleCI project env var.
  Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [agent-install.json](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install.json).

- `GITHUB_PERSONAL_ACCESS_TOKEN`
  Needed for branch protection and Greptile repo verification. The docs call out `repo` and `admin:repo_hook` scopes for branch protection.
  Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md).

- `GREPTILE_API_KEY`
  Needed in CircleCI for the `greptile-review` job.
  Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [agent-install.json](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install.json).

- `LINEAR_API_KEY`
  Needed only if the repo uses the Linear sync job.
  Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [agent-install.json](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install.json).

- CircleCI project settings access
  Harness can verify env vars if credentials exist, but it cannot create those project env vars for you.
  Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md).

- Greptile GitHub App installation
  Harness can verify whether it is installed; it cannot install the app for you.
  Source: [agent-install-guide.md](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install-guide.md), [agent-install.json](/Users/jamiecraik/dev/Agent-Skills/utilities/coding-harness/references/agent-install.json).
