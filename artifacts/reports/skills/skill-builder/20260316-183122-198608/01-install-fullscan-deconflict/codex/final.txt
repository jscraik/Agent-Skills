## Scope and triggers
- `skill-builder` is active in `install-distribute` mode for this request.
- For this first step, I will require a **full-scan deconflict** against all installed **operational** skills in the chosen scope before any install/update write.
- Default deconflict exclusions are now enforced: `.system` skills and meta/creator scaffolding skills (including `skill-creator`) are excluded unless you explicitly request inclusion.
- If deconflict returns `merge`, `fold`, or `improve-existing`, I will pause and not proceed with `install-new` unless you explicitly override.

## Required inputs
- Incoming skill source: curated name, repo URL, or local path.
- Destination scope: `REPO` or `USER`.
- Operation intent: `dry-run`, `install`, or `update`.
- Overwrite consent if destination already exists.
- Optional include override: any system/meta skills you want included in overlap analysis (default: none).

## Deliverables
- Capability overlap matrix: incoming skill vs all installed operational skills (post-exclusion set).
- Explicit deconflict decision record: `merge|fold|improve-existing|install-new` with rationale.
- Safe next-action plan based on the decision.
- If you choose to proceed after decision: validation plan and expected checks.

## Failure mode
- If installed-skill inventory cannot be resolved for the selected scope, I will stop and return a blocker summary instead of guessing.
- If deconflict indicates non-`install-new`, I will hold install actions until you confirm override.
