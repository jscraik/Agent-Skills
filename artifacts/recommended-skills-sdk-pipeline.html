Author Golden Path

The first screen should show what a skill author does next, not the whole platform. Deep security, policy, eval, and release machinery stays behind progressive disclosure until risk increases.

Hero command: skill check. It classifies the skill, runs the cheapest useful gates, explains the next blocker, and reveals heavier checks only when scripts, secrets, sharing, runtime access, or publication require them.
1 Choose Template Minimal, scripted, plugin, or full-lifecycle skill template with the right starting risk tier.
2 Edit SKILL.md Keep the surface thin: trigger, inputs, procedure, validation, handoff, failure modes, gotchas, and references. Do not force governance detail into visible headings.
REF Ingest Knowledge Deterministic scripts extract screenshots, videos, transcripts, PDFs, docs, and Markdown; each expert viewpoint or evidence source becomes one bounded reference file.
3 Run skill check Schema, references, secrets, sandbox, eval, package, and release gates are selected by risk tier.
CLI Use SDK Facade Keep ./bin/ask as repo control plane; expose skill check, skill refs ingest, skill tier, skill eval, and skill package as the author-facing facade.
ORG Load SDK Toolchain Standalone CLI installs into users, projects, CI, or organisations; project config controls local policies, templates, registries, and install scopes.
4 Fix Next Blocker One typed blocker at a time, with evidence, reason, owner, and the next useful command.
5 Eval / Package / Verify Internal rubrics first; then sandbox/dev-eval; then Tessl as third-party confirmation after pass.
SDK Use Factories factory-router deterministically chooses skill-factory or plugin-factory; plugin-factory has its own create, scaffold, manifest, bundle, validate, install, publish, and upgrade surface.
LOC Choose Install Scope Install preview lets users choose global ~/.codex or ~/.agents, project ./.codex/skills, workspace .agents/skills, with rollback receipts.
SEC Security Review security-reviewer skill plus adapters: CodeQL/Semgrep, Snyk or OSV/Grype/Trivy, BetterLeaks stack, OPA policy, and OWASP LLM checks.
HITL Show Workbench Visualise phase timeline, active agent action, approvals, evidence drawer, diffs, receipts, and rollback so humans stay in the loop.

AX Product Doctrine

UX plus DX becomes AX: Agent Experience. The SDK designs the collaboration loop where humans and AI agents build, test, evaluate, deploy, operate, and improve skills together.

Engineering doctrine: hide complexity from the user, enforce quality through the system, preserve context across time, and deliver work that is ready to use.
Thin surface. Strong guardrails. Durable memory. Professional output.
Thin SurfaceMinimal commands, minimal UI, low cognitive load, normal-case defaults, and deep modules that hide compiler, security, eval, registry, and runtime mechanics.
Strong GuardrailsValidation before execution, clear schemas, safe defaults, repeatable workflows, typed diagnostics, dry-run plans, approvals, and fail-closed release gates.
Durable MemoryDecisions, evidence, source trust, context, corrections, incidents, eval results, and ownership persist with provenance, freshness, retention, and deletion rules.
Professional OutputProduction-ready packages, readable README files, evidence-backed conclusions, consistent receipts, polished docs, and artifacts that can be used without cleanup.
Progressive DisclosureShow the next useful action first; reveal IR, traces, permissions, eval detail, policy reasons, and raw evidence only when the user or agent needs that depth.
Token EfficiencyPrefer compact context slices, source digests, receipts, summaries, retrieval budgets, and deterministic scripts so agents spend tokens on judgment rather than re-reading clutter.
Cognitive Complexity BudgetGate new commands, flags, schema fields, error classes, and workflows against user decisions, agent planning burden, and reviewer comprehension cost.
Agent ExperienceDesign for human-agent collaboration: shared plans, authority leases, resumable handoffs, inspectable evidence, predictable tools, and outputs both sides can trust.

Agent Execution and Control Plane

The SDK is agent-native: agents author, plan, delegate, execute, review, hand off, resume, and produce evidence under explicit authority boundaries.

Agent-native rule: a skill can become delegated authority. Every agent action needs an actor identity, human sponsor or principal, autonomy level, tool grant, context bundle, approval decision, and receipt.
Agent Actor ModelAgent id, model/runtime id, host/workspace id, thread/run id, invocation source, auth session binding, sponsor, principal, loaded package digest, impersonation constraints, and revocation scope.
Autonomy Gate MatrixTiers plus allowed transitions, fresh lease/approval for escalation, automatic downgrade on incidents, stale evidence, budget breach, connector auth drift, or repeated approval denial.
Delegation PolicyParent remains accountable for child work, join/cancel/drain rules, orphan detection, child budget and lease inheritance limits, and no self-expanding authority.
Per-Call Approval LedgerNormalized argv/input digest, cwd, env allowlist digest, resource selector, connector account, sandbox profile, prompt shown, approver authority, expiry, replay protection, and reapproval on mutation.
Handoff PacketSigned envelope for task, authority, context summary, memory access, tool grants, return contract, reviewer, and disposition.
Memory ContractEphemeral vs durable memory class, write proposal/review/promotion path, correction and deletion requests, conflict resolution, compaction attribution, source revalidation, poisoning quarantine, and retention enforcement.
Authority Lease SetIssuer, holder, principal, action, resource selector, data class, autonomy tier, tool grants, issued-at, expires-at, renewal policy, revocation handle, parent lease id, and fail-closed checks.
Human Control PointsApproval UX, reviewer load, escalation SLA, override record, disagreement handling, appeal path, and no silent timeout approvals.
Agent Incident ResponseContain runaway delegation, unsafe tools, secret exposure, hallucinated authority, high-cost loops, and bad rollback.

Full Skill Lifecycle

The package pipeline below is the compile and release center. The full lifecycle wraps it with discovery, operation, monitoring, update, rollback, and retirement.

A skill is not done when it validates. It stays alive through runtime evidence, user feedback, security findings, stale context, dependency drift, and revoke or deprecation decisions.

Done: project install lifecycle Install preview, real project install, lockfile updates through install receipts, project conformance, rollback, and uninstall are implemented or preview-backed.
Done: advisory review control plane SDK lenses, lens-routed review plans, review handoff receipts, and determinism audit are implemented as read-only evidence surfaces.
Current: PU-031 security adapter discovery PU-031 keeps the security lane preview-only: local adapter discovery can report configured scanner surfaces, but scanner execution, credentials, network, and mutation remain blocked.
Partial: local docs and previews Static HTML artifacts and preview commands are available, but hosted explorer publishing and remote registry surfaces remain outside the implemented SDK.
Blocked: signing and sandbox Signing needs key ownership and redaction policy. Sandbox needs a selected provider and adapter contract before execution receipts can be real.
Deferred: hosted eval and scanner adapters Reference ingestion and local eval runner receipts exist; hosted eval providers and real scanner execution adapters still need separately approved slices.
Deferred: package compiler and emitters Typed IR ownership, compiled package pipeline, emitter adapter contracts, and CI adoption gates still need scoped slices.

Public SDK Surface

The architecture also needs a concrete product surface: stable commands, API contracts, schemas, examples, diagnostics, extension points, and install UX.

SDK lens: every command returns a stable JSON shape, exit code, error taxonomy, evidence path, and human-readable explanation.
Deep Module BoundaryCommands expose intent, not pipeline internals; parsing, validation, policy, eval, signing, emission, and evidence stay behind stable contracts.
Golden Path`skill init -> skill lint -> skill eval -> skill package -> skill install --local -> skill publish --dry-run`, with expected receipts, next actions, and blocked/degraded states.
Thin Command PrincipleNormal use collapses to create, check, run, package, install, publish, and manage; advanced verbs live behind subcommands, `--explain`, or drill-down views.
API SurfacesCLI, Python/TypeScript bindings, local JSON-RPC or MCP API, hosted registry API, and webhook/event API declare auth, versioning, pagination, retries, and rate limits.

Evals are necessary, but they are not the whole testing story. A Skills SDK needs a context-driven testing layer that asks what matters, what could fail, how we would notice, and what evidence should change a release decision.

CI, Hooks, Review, and Adoption Gates

The SDK should feel fast for ordinary skill authoring and strict only when risk justifies it. Local hooks, CI, security checks, and review agents are staged so authors get the next useful action instead of platform ceremony.

Adoption rule: security scales with risk. A draft skill should not pay the cost of a published privileged package, but the moment a skill asks for scripts, secrets, runtime access, or publication, the gates tighten automatically.
Prek Local Hooks Use Prek as the default hook runner for fast, deterministic pre-commit and optional pre-push checks. gates format, docs lint, schema check, secret scan, changed-file validation, lightweight smoke.
CircleCI Main CI CircleCI owns heavy deterministic workflows: build, unit/integration tests, package proof, docs, compatibility, eval runs, and artifacts. requires restricted contexts, context policies, 1Password/secret broker integration, artifact receipts.
GitHub Actions Security GitHub Actions owns GitHub-native trust: CodeQL, Dependabot, secret scanning, OIDC, branch protection, and required checks. requires least-privilege permissions, protected branches, no broad write tokens, check policy by tier.
CodeRabbit Review Use CodeRabbit CLI for pre-push or agent-readable review and PR review for independent, context-aware feedback. requires non-author reviewer lane, JSON findings where useful, false-positive triage, no blind blocking on low-risk diffs.
Tier 0 Draft Skill Goal: preserve usefulness while shaping early ideas. Run README/SKILL.md presence, schema parse, and Prek basics only. skip signing, SBOM, full evals, sandbox receipts, release review.
Tier 1 Local Utility Goal: safe personal productivity. Add lint, validate, minimal eval, references quality check, and changed-file smoke. skip package signature unless shared, registry, full provenance.
Tier 2 Scripted Skill Goal: scripts run safely. Add script validation, secret scan, sandbox dry run, env allowlist, parser-first review, and eval dataset. block shell eval, raw env dumps, unreviewed regex on critical paths.
Tier 3 Shared Team Skill Goal: team reuse. Add signed package, provenance, SBOM, CodeRabbit/agent review, CircleCI checks, and owner approval. requires changelog, compatibility check, rollback path, support owner.
Tier 4 Privileged Runtime Goal: constrained power. Add 1Password secret broker, policy-as-code, sandbox receipt, security review, full eval suite, and reattestation. block missing authority lease, stale policy, weak secret tainting, unapproved egress.
Tier 5 Published Package Goal: supply-chain trust. Add Cosign, Gitsign, SLSA/in-toto, registry metadata, install preview, decommission plan, and release waiver policy. requires signature, provenance, SBOM, vulnerability gate, rollback, archive disposition.
Golden Path CLI Expose simple commands while the SDK picks gates by risk tier: init, check, eval, package, publish. must show current tier, next useful command, blockers, evidence, and skipped heavyweight gates.
Overreach Control Do not block adoption with maximum ceremony by default. Heavy gates activate on sharing, scripts, secrets, runtime access, registry, or publication. requires waiver expiry, risk owner, cost/latency budget, and escalation path.

MVP and Tightening Decisions

This is the adoption guardrail for the whole map. The SDK can contain deep security, eval, and governance machinery, but the default author path stays small and risk-scaled.

Decision rule: build the smallest useful SDK first, then activate heavier capabilities only when a skill introduces sharing, scripts, secrets, runtime access, external installs, registry distribution, or publication.
Smallest Useful SDK V1 should be templates, schema validation, Skill IR, risk-tier classifier, `skill check`, internal eval dataset, package manifest, signing interface, Prek hooks, CI policy map, install preview, and core receipts. surface init, check, eval, package, verify.
V1 Scope Layers Separate V1 product surface from V1 core contracts and later platform capabilities. Build schemas, risk tiers, receipt schema, install scopes, eval dataset schema, and security adapter interfaces before marketplace or dashboard UX. defer full marketplace, compliance receipts, broad governance platform, fancy HITL dashboard, Cedar default, and required Tessl.
Skill Story and Use Case Every skill should connect Card, Conversation, and Confirmation: short SKILL.md, captured decisions/context, and evals/receipts. Complex skills add use-case fields: scope, goal level, actor, trigger, guarantees, main success, extensions, and open issues. check skill story, acceptance criteria, skill smells, and confirmation coverage.
Missing Core Contracts Do not leave receipt schema, deterministic exit codes, skills.lock.json, trust store, migration/diff system, quarantine, uninstall, and plain-language diagnostics implicit. backbone shared receipts plus clear blocker explanations.
Safe To Run Question A skill can run only when schema is valid, permissions are declared, secrets are scoped, sandbox policy is known, source/context trust is acceptable, and runtime blockers are resolved. output allow, allow-with-review, blocked, quarantined, rollback-required.
Optional Until Risk Rises Signing, SBOM, full evals, Tessl, deep security review, provenance, and release governance are not mandatory for every draft; they trigger by risk tier. protects adoption and early usefulness.
Skill IR Purpose Skill IR exists to power validation, security review, emitters, eval generation, docs, compatibility, and install previews. If it does not serve those jobs, it is ceremony. block IR fields with no validator, emitter, eval, or receipt consumer.
Failure Model Missing evidence, unsafe runtime, stale context, weak eval, unsigned package, leaked secret, poisoned state, broken migration, and external setup blockers each need a clear blocked state and next command. never convert unknown evidence into pass.
Governance Is Not A Separate SDK Keep governance as gates, receipts, ownership, waivers, release decisions, and audit trails. Do not create a heavy Governance SDK product surface in v1. defer broad governance platform features.
Policy Choice Pick OPA/Rego as the default policy adapter because it is broad, mature, and fits deny-by-default runtime/install decisions. Keep Cedar as a later adapter if authorization modeling demands it. avoid exposing policy language complexity to normal skill authors.
Registry MVP Do not build a full marketplace early. Start with local package, install preview, digest tracking, ORAS/OCI feasibility, and signed package verification. defer marketplace, ranking, discovery UX, and public publishing workflows.
Docs And Explorer MVP Build public capability docs and a read-only Skill Explorer before a registry. Docs explain package contracts; the explorer demonstrates signatures, permissions, evals, receipts, freshness, trust, and install preview from static manifests. surface docs.yourdomain.com, skills.yourdomain.com, generated references, static skill index, and no public marketplace in v1.
Eval Confirmation Ladder Internal tests and rubrics are source-of-truth. Then run sandbox/dev-eval external checks for independent scoring. Tessl is third-party confirmation after internal pass. sequence internal -> sandbox/dev-eval -> Tessl.
Knowledge Trigger Rule Knowledge engineering is not for every tiny skill. It activates when the 360-character skill surface pushes important instructions, context, runbooks, source truth, or examples into references. check freshness, accuracy, contradictions, source trust, and task usefulness.
Sandbox Where It Matters Sandbox external skill installs before trust, sandbox scripts/runtime execution, and use Sandbox A/B lanes to compare before/after skill behavior with LLM-as-judge and deterministic oracles. not needed for pure static authoring or docs-only draft checks.
Start With Five Receipts Do not implement every receipt upfront. Start with check, package, signature, eval, and runtime receipts; add registry, decommission, and compliance receipts when tiers require them. keeps evidence useful rather than noisy.
Adapter Detection The SDK should detect Prek, Cosign, Gitsign, 1Password, BetterLeaks, OPA, ORAS, Syft, scanners, and sandbox support, then degrade gracefully with clear install/setup guidance. output available, missing, misconfigured, blocked, or optional.
Compatibility Checker Map Minor, Moderate, and Major changes to migration, eval, signing, docs, and release requirements so authors know why a change became expensive. prevents accidental breaking skill updates.
Redaction And Taint Rules Prompts, logs, traces, eval outputs, memory writes, CodeRabbit findings, and review-agent artifacts must preserve secret/data taint and redact before persistence. block raw env dumps and secret-derived leakage.
Anti-Bloat Rule If a feature does not improve author speed, safety proof, runtime trust, eval quality, install confidence, or release decisions, keep it out of v1. question what user or agent decision this feature improves.
Not V1 / Deferred Full marketplace UX, broad governance platform, Cedar as default policy, compliance receipts, public registry ranking/discovery, and full knowledge packages for tiny skills stay out of MVP. defer until real install volume, team sharing pressure, enterprise policy need, or release evidence demand proves the cost.

Package Hardening Overlay

These checks run across the pipeline. They treat a skill like executable software: versioned, signed, sandboxed, permissioned, reviewed, evaluated, and monitored for state and data-flow abuse.

Default stance: a skill inherits too much power until the SDK proves where its instructions came from, what it can access, how it runs, what state it persists, and which flows are forbidden.
Version ControlEvery source, generated artifact, eval pack, and release decision is tied to a version, digest, and changelog.
OSS Dependency AssumptionSigstore, Cosign, Gitsign, BetterLeaks, 1Password, OPA, ORAS, Syft, and scanners are adapters with pinned versions, receipts, and fallback behavior, not unreviewed ambient tools.
Surface Area CreepNew commands, flags, schema fields, and UI states can make the SDK feel powerful but expensive to understand; doctrine gates require a clear user or agent payoff.
Progressive Disclosure FailureDumping every diagnostic, trace, permission, and receipt at once increases cognitive load; default surfaces should show the next useful action and reveal depth on demand.
Token WasteAgents can burn context on duplicated docs, stale references, verbose receipts, and whole-package reads; compact summaries, source digests, and retrieval budgets are enforced.
AX BreakdownHumans and agents lose trust when authority, state, evidence, next action, or handoff responsibility is unclear.
Unprofessional OutputPassing evals is not enough if artifacts still need cleanup; reports, README files, receipts, generated packages, and docs must be ready to use.
Cryptographic SignaturePackages need signer identity, digest verification, provenance, and signature failure as an install blocker.
Transparency Privacy LeakPublic transparency logs can expose metadata about private skills; the SDK needs public, private, keyful/KMS, and offline verification modes.
Key GovernanceSigning requires key identity, issuer policy, timestamping, rotation, revocation lists, and offline verification behavior.
Guardrails and RunbooksReferences include operational runbooks, escalation paths, data handling, and prompt-injection rules.
Context Corpus`references/context*.md` is useful steering, but must be freshness-checked, source-labeled, and contradiction-scanned.
Knowledge Dumping Ground`knowledge/` needs source quality, canon/non-canon boundaries, freshness, confidence, owner review, and promotion rules so it does not become untrusted clutter.
Biased Knowledge CapturePoor interviews and cherry-picked sources create brittle skills; discovery should collect observed evidence, edge cases, and counterexamples.
Compliment-Driven ContextPositive feedback, approval, or enthusiasm is not evidence unless anchored to behavior, cost, commitment, or a concrete next step.
Hypothetical DemandFuture-tense promises and generic claims should not shape skill requirements without past examples, current workarounds, or costly signals.
Wrong Segment LearningConversations with impressive but unrepresentative people can poison context; discovery needs focused, findable, behavior-backed segments.
Conversation BottleneckOne person summarizing discovery can distort the skill model; important interviews need notes, team review, and decision receipts.
Tacit Knowledge LossSME nuance must be turned into explicit glossary, assumptions, examples, decisions, and eval cases before it can survive runtime use.
Externalization GapExpert judgment can be captured as anecdotes but never converted into usable rules, examples, schemas, or eval cases.
Combination Without UnderstandingMerging documents can create explicit clutter unless the SDK checks contradictions, vocabulary alignment, and task relevance.
Internalization FailureKnowledge is not truly reusable until authors, agents, and reviewers can apply it in examples, drills, evals, and runtime decisions.
Knowledge Owner GapWithout domain leads connecting strategy, frontline evidence, and external experts, package knowledge loses direction and accountability.
Shallow Reading RiskSources should not be promoted from skimmed notes alone; important material needs structure, terms, claims, arguments, criticism, and relevance captured.
Uncriticized AuthorityA trusted source can still be incomplete, outdated, irrelevant, or wrong for the target skill; appraisal and source limits must travel with the claim.
False SynthesisSyntopical comparison can erase disagreement; the SDK should preserve contradictions, minority views, and unresolved questions instead of forcing consensus.
Weak Context Degrades Good SkillsEvals cover the whole package, not only SKILL.md, because stale, thin, contradictory, or low-quality references can make a well-authored skill perform badly.
Sandboxed A/B EvalsCandidate skills run in isolated eval sandboxes before promotion, including native macOS lanes where needed.
Deterministic ScriptsRepeatable mechanics move to scripts with structured parsers; regex is reviewed and minimized for critical paths.
Prompt Injection ReviewEnglish-language instructions, fetched pages, and user-provided content are scanned for instruction hijacking.
Persistent State PoisoningData at rest is scoped, validated, resettable, and treated as untrusted input on every load.
Toxic Flow ControlBlock exfiltration paths for emails, secrets, webhooks, API calls, files, and unapproved destinations.
Resource AccessSkills do not silently inherit broad filesystem, network, browser, token, or environment permissions.
Runtime Enforcement GapGovernance is decorative unless every runtime call is checked against policy at the moment of use; missing policy must deny by default.
Trust BoundariesFetched URLs, stale content, generated outputs, and external references carry freshness and trust labels.
Instruction Boundary CollapseFetched pages, tool outputs, memory, user files, and MCP results can become hidden instructions unless taint labels keep data separate from authority.
Execution ContextEnv vars, filesystem roots, network access, shell commands, and native capabilities are declared and constrained.
Native Sandbox EscapeSandbox receipts record declarations and observations; install or run blocks unless containment assumptions are validated for the target OS.
Native Binary First RunUnsigned, unnotarized, dylib-loaded, postinstall-scripted, or unexpected-network native binaries can bypass the skill-level trust model before policy catches up.
Roles and RBACFine-grained permissions map actors, reviewers, publishers, runtime roles, and approval gates.
Separation-of-Duty FailureSelf-approval, stale group membership, cross-tenant connector use, and break-glass without expiry can turn RBAC into ceremony.
Agent Authority ExpansionAgents and subagents cannot grant themselves new tools, memory writes, secrets, network, publish rights, or delegation depth.
Secret Broker PolicySecrets are leased by audience, scope, actor, and duration; raw ambient env is denied and traces/memory are redacted before persistence.
Secret Provider Drift1Password Environments is an adapter choice; beta behavior, vault permissions, service-account scope, local mounts, and CI sync need explicit receipts and fallback policy.
Secret Taint LeakageSecret handles, derived values, logs, prompts, tool args, state, and traces need taint tracking or redaction can miss indirect exposure.
Runaway DelegationContain high-cost loops, repeated approval failures, unsafe tool attempts, hallucinated authority, and unresolved child-agent work.
Floating Invocation IdentityEvery run binds agent id, host/workspace, auth session, thread/run id, model/runtime, connector account, and package digest.
Expired AttestationSkills cannot remain trusted indefinitely; stale evidence, owner drift, dependency advisories, host/model changes, or permission changes force reattestation.
Orphaned OwnershipMaintainer handoff, backup owner, support-channel verification, stale-owner escalation, and orphaned package freeze rules prevent abandoned runtime authority.
Archive Privacy ConflictEvidence archives retain immutable metadata while sensitive payloads follow redaction, deletion/export, legal-hold, and retention-exception procedures.
Emitter Write DriftEmitters use transaction write plans with ownership markers, hashes, conflict checks, smoke commands, and rollback plans before generated files are integrated.
Change Classification DriftMinor wording, Moderate procedure, and Major new-topic changes require different review depth, migration evidence, and re-eval scope.
Tessl Gate ConfusionTessl private workspace checks are post-internal-gate evidence; they do not replace canonical rubrics, internal evals, or release ownership.
Release Waiver DriftWaivers expire, name a risk owner, block critical security/privacy/reproducibility issues, and cannot bypass autonomy gates.
Operational Blind SpotsMissing SLOs, owners, alert thresholds, support channels, or rollback drills block promotion to runtime use.
Supply Chain DriftSBOM, license, vulnerability, dependency freshness, native binary, and maintainer trust findings can freeze release.
Maintainer CompromiseSigned packages can still be risky when maintainer keys, dependencies, native binaries, or lifecycle scripts are compromised; provenance and reproducibility must be checked.
Plugin Hook TrustBundled hooks are not trusted merely because a plugin is installed or enabled; hook definitions require explicit review.
MCP Host Boundary CollapseMCP tool descriptions and results are untrusted data; host env access, connector account drift, and tool-result taint need isolation and revocation.
MCP Approval DriftPlugin MCP servers need auditable enabled-tools lists and per-tool approval policies so host config changes do not silently widen access.
Install Cache DriftCodex loads installed plugin copies from cache, so release evidence must identify the installed copy, not only the marketplace source.
Plugin Data BoundaryWritable plugin data is separate from plugin source and should be scoped, resettable, and treated as runtime state.
Evaluator False ConfidenceLLM judges can miss failures or over-alarm; release gates need ground truth, TPR/TNR, calibration, and bias correction.
Insufficient Evidence Mistaken for PassMissing eval coverage, stale source quality, judge drift, Tessl setup blockers, or no production sampling must block as unknown quality, not quietly pass.
Trace PrivacyObservability can capture prompts, user data, tool outputs, secrets, and context; traces need minimization, redaction, and retention policy.
Sampling BiasProduction evals can overfit to visible users and common paths; sample across dimensions, affected groups, and rare high-risk cases.
Unjustified Causal ClaimsEvaluation evidence must distinguish correlation, prediction, and causal impact before governance relies on the claim.
Core Rule Canonical source is edited. Skill IR is analyzed. Emitters generate projections.
Safety Rule Generated runtime artifacts are never evidence of source ownership or package trust.
Release Rule A skill is complete only when gates produce thresholded evidence, required approvers, valid authority leases, signature proof, readiness, and a promote, rollback, revoke, or blocked decision.
